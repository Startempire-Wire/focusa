# focusa-roadmap-to-workpoint

Bounded reusable workflow for pre-implementation reasoning: scope → authority → decisions → blockers → graph → Trajectory → Workpoint.

## When to use
Pre-implementation reasoning chain before any code change: verify project scope; discover live authority; close decisions; map blockers/risks; design order; materialize provider-neutral tasks; prepare contracts; audit graph; derive MLG → STG → Waypoint → current Workpoint; expose ready frontier.

## Tool routing
- orientation: focusa_agent_prompt, focusa_utility_card, focusa_agent_card, focusa_tool_search
- scope: focusa-project-scope (canonical project_root + continuity_id)
- state: Workset ledger, Trajectory, Workpoint, beading (bd ready/blocked)
- audit: scope discovery → execution graph → Trajectory-to-Workpoint derivation

## Steps
1. Verify project scope (canonical root, continuity, Workset)
2. Discover live authority/current state (ledger, trajectory, work_loop)
3. Close decisions (spec, requirement rows)
4. Map blockers/risks (bd blocked/ready, dependency graph)
5. Design implementation order (topological, audit)
6. Materialize tasks + dependencies (bd create, deps)
7. Prepare point-of-need contracts (schemas, acceptance)
8. Audit graph correctness (no cycles, coverage)
9. Derive MLG → STG → Waypoint → Workpoint
10. Expose first authorized ready frontier (bd ready)

## Evidence
Skill file present + runbooks reference + ownership manifest. Not admitted to locked release without separate authority (proposal only).
