## 1. Problem statement

Focusa already contains separate temporal, prediction, scoring, ontology, reflex, Intuition, worker, reducer, and client surfaces. Adding mathematics, statistics, and physics only as API endpoints would create several failures:

- numbers remain untyped strings in ordinary cognition;
- tools return answers without Workpoint or Evidence integration;
- Secondary Cognition cannot formulate or challenge models;
- reflexes remain advisory names without executable behavior;
- ontology vocabularies stay hard-coded in client routes;
- computation results bypass reducer authority;
- compaction loses equations, assumptions, and uncertainty;
- predictions cannot prove model lineage;
- learning promotes conclusions without quantitative validity;
- Pi, CLI, MCP, TUI, Mission Canvas, and generated clients diverge;
- human learning remains separate from real project work.

This specification defines the cross-cutting implementation contract that prevents those outcomes.

## 3. Foundational laws

1. Quantitative applicability is detected, not globally assumed.
2. Nonquantitative missions are not burdened with irrelevant mathematical context.
3. Applicable quantitative claims use typed quantities rather than prose-only numbers.
4. Ontology is generated from core registries, not duplicated as route-local arrays.
5. Reflexes are small typed contracts with explicit execution classes.
6. Secondary Cognition proposes; it does not mutate canonical state.
7. Intuition emits explainable signals; it does not command or block directly.
8. Focus Gate selects salience; it does not grant authority.
9. Deterministic guards may block invalid quantitative actions according to policy.
10. Canonical state changes require reducer events.
11. Large data and computation artifacts remain behind handles.
12. Workpoints carry active quantitative contracts and proof obligations.
13. Compaction preserves active model state without embedding raw datasets or solver traces.
14. Predictions bind the exact quantitative/statistical/physical model lineage.
15. Learning promotion requires the applicable quantitative-scientific proof.
16. Tools and clients project one Operation Registry.
17. Mission Canvas visual focus is not mathematical or scientific authority.
18. High-consequence deterministic loops remain free of LLM execution.
19. Every surface reports truthful `schema_only`, `degraded`, `blocked`, `experimental`, or `verified` status.
20. Missing integration on any activated surface blocks full conformance.

## 8. Secondary Cognition

- identify quantitative structure;
- extract quantities and units;
- propose equations, assumptions, constraints, and models;
- propose statistical protocols;
- propose physical laws and experiment plans;
- generate countermodels and counterforecasts;
- rank unknowns;
- propose sensitivity and decision-frontier analysis;
- generate conjectures and counterexample searches;
- explain computation and measurement results.

It MUST NOT:

- mint canonical measurements;
- alter quantities or models directly;
- claim formal proof;
- settle experiments;
- resolve predictions;
- promote learning;
- mutate live market or actuator policy;
- bypass reducer, authority, or verification.

## 17. Reducer invariants

1. Canonical quantities have valid identity and representation.
2. Measured quantities include measurement, uncertainty, source, and temporal provenance.
3. Observations are immutable; corrections append and supersede.
4. Simulation results cannot enter observation collections.
5. LLM-generated equations and models enter as candidates.
6. Statistical inference references a frozen protocol.
7. Physical models declare frames and applicable conditions.
8. Computation completion requires immutable inputs and provider identity.
9. Randomized runs bind a seed policy.
10. Formal proof status requires an eligible proof provider.
11. High-consequence results bind Spec 144 verification.
12. Predictions cannot claim model support from absent or unverified runs.
13. Learning cannot promote from invalid, contaminated, unstable, or physically impossible inputs.
14. Large artifacts use Reference Store handles.
15. Every accepted change includes Evidence and Receipt lineage.
16. Client-originated canonical sequences are rejected or reassigned by writer authority.
17. Unknown future schema content cannot influence action or settlement.
