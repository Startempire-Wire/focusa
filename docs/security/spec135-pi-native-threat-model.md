# Spec 135 Pi-native Mission Canvas threat boundary

The interactive Mission Canvas runs inside the current Pi terminal through the Pi TUI custom component. There is no browser, webview, sidecar, localhost renderer, or separate rich-host process to authenticate.

## Assets

- canonical `ResolvedWorkspaceProjection` fields;
- current Pi session and prompt editor;
- operator-entered references and draft text;
- terminal output and interaction state.

## Controls

1. Projection strings pass through control-sequence and control-character sanitization before emission.
2. The renderer emits only bounded text rows and color escape sequences generated by trusted local code.
3. Input is constrained to explicit Mission Canvas actions; unknown actions are ignored.
4. The shell is mounted and disposed through Pi's `ctx.ui.custom()` lifecycle, restoring stock Pi on OFF.
5. Canonical state remains in Focusa Core; the view cannot write projection authority or invent contributions.

## Residual risks

Terminal emulators remain responsible for interpreting trusted renderer styling sequences. Projection text is treated as hostile and sanitized before it reaches those sequences. UIAI is limited to bounded fixture/evidence evaluation and cannot become the interactive authority.
