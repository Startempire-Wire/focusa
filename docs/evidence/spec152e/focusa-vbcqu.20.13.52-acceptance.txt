Bounded result
- Added the key-quarantine ledger. quarantineRecord() quarantines the four
  named record classes — synthetic focusa_live rows, duplicate EDD/custom
  keys, orphan payment IDs, and unresolved products/accounts — one ledger row
  per record handle, idempotent on replay, storing only the 64-hex key digest
  (sha256 of the key/payment id/product code/account handle), a masked key, a
  keyed email lookup digest, and a pinned evidence digest. Every quarantine
  reason is the surface's fail-closed registered code (EDD_ORDER_UNVERIFIED,
  LICENSE_ACCOUNT_MISMATCH, ACCOUNT_MERGE_REVIEW_REQUIRED,
  PRODUCT_MAPPING_REQUIRED, EDD_CUSTOMER_RESOLUTION_FAILED); no raw key, raw
  email, payment id, or secret is ever stored or returned.
- activationLeaseGate() denies new activation/lease from quarantined records:
  any unresolved quarantined row denies with its recorded reason; a
  settled-denied record denies; an unledgered key carrying a synthetic prefix
  (focusa_live_*, synthetic_*, local_*, eval_*) denies fail-closed without any
  ledger row; an explicitly approved canonical record (settled_approved) passes
  — synthetic records require that separate operator approval and never pass
  silently; a canonical key absent from the ledger remains usable.
- Canonical selection only with proof: selectCanonicalKey() requires the keyed
  identity digest to equal the candidate's stored digest plus evidence-backed
  provenance; the same proof matching two duplicates is ambiguous and fails
  closed (ACCOUNT_MERGE_REVIEW_REQUIRED) with the ambiguity journaled; a key
  group can never hold a second canonical; replays return the stored
  settlement. The winner is settled_approved; the other duplicates stay
  quarantined until an explicit operator settlement.
- Explicit operator review/settlement path: settleRecord() with a bounded
  operator audit identity, a proof-backed approval reason (PROOF_BACKED_
  SELECTION with evidence) or a bounded denial code, one settlement per record
  (replays dedupe; different decisions conflict with IDEMPOTENCY_CONFLICT).
  listQuarantined() is the bounded digest-only review queue with exact state
  counts. Rollback is preservation-only: the ledger, settlements, and journal
  are never deleted and EDD customer/order/refund truth is never touched.
