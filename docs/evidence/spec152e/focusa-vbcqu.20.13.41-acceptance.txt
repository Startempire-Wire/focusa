Bounded result
- No PowerShell branch can issue Evaluation or entitlement: the bootstrapper
  contains no local validation, no license/authority/receipt JSON issuance,
  no self-Eval or installer grace license, no raw key/email parameter or
  storage, and no legacy registry validation endpoint. Raw credentials
  (`-LicenseKey`, `-Email`, `-Registry`, and any secret/token/credential-like
  stray argument) are rejected by the presenter-safe argument gate with
  `E_AUTHORITY_RAW_KEY_FORBIDDEN` before any state or network I/O; unknown
  options fail closed.
- Activation intent is collected or forwarded, never decided: `-Eval`
  forwards intent to the shared activation client in the Rust installer;
  help text, parameter docs, and dry-run telemetry now state explicitly that
  Evaluation is authority-issued only and never local (`evaluation:
  authority-issued only; intent forwarded to the shared activation client`
  appears in the dry-run plan when `-Eval` is set). No-key Windows installs
  enter the Rust authority activation journey, never local Evaluation.
- Artifact verification, rollback, recovery, and uninstall are preserved:
  SHA256SUMS verification with stable-only Cosign fail-closed, bounded temp
  cleanup on interruption, `E_INSTALL_INTERRUPTED` recovery messaging, and
  preserve-by-default delegated uninstall (`--keep-data` without explicit
  `-PurgeData`) are intact; the install path converges on exactly one
  fail-closed handoff (`& $Focusa @Args` occurs once) with allowlisted flags
  only — no caller-controlled product/price/grant/feature/limits input.
- Semantic parity with Unix: the PowerShell bootstrapper now rejects the
  same raw credentials with the same `E_AUTHORITY_RAW_KEY_FORBIDDEN` code,
  discloses the same authority-issued-only Evaluation wording, forwards
  `--eval` intent the same way, and preserves the same rollback/uninstall
  posture as scripts/install-focusa.sh (atom 20.13.40).
