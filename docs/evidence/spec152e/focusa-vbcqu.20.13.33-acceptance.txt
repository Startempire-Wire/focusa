Exact surfaces (this atom only)
- EDD transactional license email: FocusaSpec152eTransactionalMailAdapter::
  sendLicenseDelivery() sends the branded license email with product and order
  identity, the full human license key, safe activation instructions,
  account-management and recovery links, and support information; no
  promotional content. Delivery attempts, bounces, and suppression are
  recorded by the caller with masked outcomes only; the plaintext key never
  returns or logs through the adapter.
- Registration delivery state: the activation registration gains
  email_delivery_status / email_delivery_attempts / email_delivered_at /
  email_delivery_outcome (bounded values, PHP-enforced) with an idempotent
  upgrade path (addColumnIfMissing) and a bounded, idempotent
  recordEmailDeliveryState() repository surface; the presenter snapshot
  exposes the masked email delivery status.
- Dual-delivery coordinator: docs/contracts/spec152e-dual-delivery-
  coordinator.v1.php — FocusaSpec152eDualLicenseDeliveryMigration journals
  one delivery record per registration (wp_wpuiai_dual_license_deliveries)
  holding the canonical license_key_digest/mask plus per-channel status,
  attempts, timestamps, masked outcome, resolved state, and sealed recovery
  envelope; settlement resolves the ONE canonical EDD key from
  wp_edd_licenses (never mints), sends the license email, and confirms the
  terminal channel resolved the same license ID/key
  (noteTerminalDelivered fails closed with DUAL_DELIVERY_KEY_MISMATCH on any
  digest/license divergence).
- Recovery/reissue service: coordinator recover() requires the registration's
  poll credential (authenticated recovery), re-delivers the SAME canonical
  key through the failed channel — email re-send with masked outcome
  journaling, or a fresh one-time device-encrypted terminal envelope (same
  license, same key digest) — and never creates a second key. Recovery is
  refused once both channels are settled (DUAL_DELIVERY_ALREADY_SETTLED) and
  fails closed while the canonical license is unusable.

Bounded result
- Added FocusaSpec152eDualLicenseDeliveryCoordinator::settle(): one canonical
  EDD key is resolved only from wp_edd_licenses (active status, canonical hex
  pattern) and delivered through the branded transactional license email
  (registered facade sender identity focusa_install_transactional_v1, full
  key in the approved §16.1 content, masked outcomes) while the terminal
  channel is marked pending. Settlement is journaled once per registration;
  a replayed settle (same idempotency key) and a repeated settle (different
  key) both return the existing journal with zero additional emails and zero
  new licenses. No response, journal, or log contains the plaintext key or
  unmasked email.
- recordEmailOutcome() maps provider events to bounded masked states
  (delivered / bounced soft|hard / complained -> failed with
  suppressed_transactional), idempotently replays per request key
  (IDEMPOTENCY_CONFLICT on changed identity), and refuses later failure
  outcomes after a delivered channel.
- noteTerminalDelivered() confirms the terminal envelope bound the same
  license ID and license_key_digest recorded at settlement (one-key rule);
  a different key or license ID fails closed with DUAL_DELIVERY_KEY_MISMATCH.
- Resolved state settles only when both channels resolve (both_delivered with
  recovery_resolved_at); partial delivery is email_only / terminal_only;
  hard bounce, suppression, provider failure, or terminal failure without any
  delivery resolves recovery_required and mints a bounded rec_ handle.
- recover() authenticates with the registration poll credential (wrong or
  expired credentials fail closed), re-delivers the SAME canonical key:
  email recovery re-sends the license email (attempts +1, never a second
  key); terminal recovery seals a fresh one-time device-encrypted envelope to
  the bound device key whose claims decrypt to the exact canonical EDD key,
  with identical-envelope idempotent replay. Unbound device keys
  (NODE_PUBLIC_KEY_REQUIRED), unusable licenses (EDD_LICENSE_UNUSABLE), and
  fully settled deliveries (DUAL_DELIVERY_ALREADY_SETTLED) fail closed.
- Partial-failure fixtures (exact verification): (A) email hard-bounce while
  terminal delivers -> authenticated email recovery re-delivers the same key;
  (B) terminal delivery loss while email delivers -> authenticated terminal
  recovery seals a fresh envelope for the same key; (C) both channels failed
  (suppressed email, revoked license) -> recovery re-delivers and both
  channels settle. Every fixture ends with the EDD license count unchanged.
- No unverified-email promotion, local/self-issued entitlement, independent
  facade authority, client-controlled price/grants, secret or unmasked
  real-email evidence, or publication.
