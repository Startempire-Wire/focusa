Bounded result
- Added the lease refresh service seam for the registered authority route
  POST /v1/lease/refresh (facade registry proxy_route lease_refresh, facade
  security POST, install-facade input allowlist node_id/refresh_credential/
  current_sequence). The caller may submit only node_id, refresh_credential,
  the advisory current_sequence, request_id, and idempotency_key; any EDD id,
  price, grant, feature, limit, tier, commercial field, lease_uuid, or sequence
  fails closed with CALLER_CONTROLLED_GRANT_DENIED, and raw email input fails
  closed with INPUT_RAW_EMAIL_FORBIDDEN.
- Refresh re-reads canonical state, never the presented client claims: the
  verified authority account (FocusaSpec152eEddAccountAdapter), the current
  lease for (account, node, product), the node binding (NODE_NOT_FOUND /
  NODE_NOT_ACTIVE / NODE_NOT_BOUND on removal/deactivation/unbinding), the
  EDD license truth (FocusaSpec152eEddLicenseAdapter: EDD_LICENSE_UNUSABLE /
  LICENSE_ACCOUNT_MISMATCH), the exact order/item/price truth
  (FocusaSpec152eEddOrderAdapter + the frozen server-owned download mapping:
  EDD_ORDER_PENDING / EDD_ORDER_UNVERIFIED), the EDD lifecycle projector journal
  per license (refund/revoke/expire/suspend/cancel/supersede postures), and the
  monotonic authority sequence (account highest_entitlement_sequence and the
  per-license journal result_sequence; STALE_SEQUENCE below the authority).
- Offline bounds: refresh is refused NOT_YET_VALID before the lease not_before
  and refused EXPIRED past expires_at + offline grace (evaluation leases have no
  grace); refresh inside the offline-grace window is allowed and re-extends the
  lease +90 days from the refresh time. Past expiry+grace there is no local
  extension — the client must re-activate through the authority.
- Rotation: when truth holds, the service issues the next strictly-monotonic
  signed lease through the EDD-bound issuer (which re-validates account/
  license/order/product/node), supersedes the presented lease
  (status superseded / refresh_rotated), chains previous_lease_digest to the
  exact prior payload digest, rotates the bounded refresh credential
  (SHA-256 digest at rest only; plaintext returned exactly once; old credential
  superseded), and appends lease_superseded + lease_issued outbox events in the
  same settlement transaction. Idempotent replay returns the same rotated lease
  and re-seeds the one-time credential; changed reuse of an idempotency key
  fails closed (IDEMPOTENCY_CONFLICT).
- Signed denial/recovery posture: refund, revoke, expiry, suspension, node
  removal, stale sequence, or unusable EDD truth produce a SIGNED
  focusa.spec152e.refresh_refusal.v1 envelope (Ed25519 under the trusted
  authority lease key, LEASE_DOMAIN) carrying account/node/product/lease refs,
  presented + authority sequences, the recovery-only posture, and the bounded
  refusal reason. The presented lease is settled to the matching terminal
  status (refunded/edd_refunded, revoked/edd_revoked, superseded/...), a
  lease_superseded or lease_revoked outbox event is appended (in-transaction,
  same as the settlement), and the signed refusal is journaled. Repeat refresh
  on an already-settled lease returns the stable signed refusal without
  re-settling or re-journaling. Stale software/state cannot restore access:
  after an authority sequence advance past the lease (e.g. refund/revoke or an
  account-level transition), the standard lease verifier rejects the old lease
  with STALE_SEQUENCE at the refusal's authority sequence, and the refresh path
  refuses it deterministically.
- Highest sequence surface: highestSequence(account, product) returns the
  account highest_entitlement_sequence, the lease sequence ledger, and the
  max (43 after the rotation scenario; the refusal carries the post-transition
  authority sequence, never below the refused lease's own sequence).
- verifyRefusal() mirrors the runtime verifier (key-set trust, signature,
  schema, reason bound, key-id, window, sequence authority) and rejects
  tampered, unknown-key, unbounded-reason, wrong-account, stale, and expired
  refusals. The routes seam resolves the registered route fail-closed and masks
  responses to the public facade allowlist (refresh credential never passes a
  masked envelope; the HTTP adapter maps REFUNDED → LICENSE_REFUNDED and
  REVOKED → LEASE_REVOKED for the existing Rust authority client's
  RecoveryOnly disposition).
- No raw email, secret, license key, or unmasked real-email evidence is
  accepted or stored; the plaintext refresh credential appears only in the
  one-time result, never in any stored row; refund/revoke/expiry settlement is
  preservation-only (EDD customer/order/license, node, lease, credential, and
  audit history are never deleted).
