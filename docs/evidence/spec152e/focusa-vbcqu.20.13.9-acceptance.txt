Bounded result
- Added ChallengeService: generates single-use magic links and OTP codes, hashes
  verifiers for storage with independent key derivation, validates submitted
  verifiers against stored hashes. Challenge kind (magic link vs OTP) is selected
  based on facade presenter capabilities. Magic links are bound to the exact
  facade origin and verification path from the registry.
- Added TransactionalMailAdapter: sends branded verification challenge emails
  using facade registry sender identity, display name, and brand assets. Magic
  link emails contain a branded CTA button; OTP emails contain a monospace code
  display. Templates are plain PHP strings with no secrets, no raw email in
  subject lines, and no promotional content. Delivery notifications are
  supported for post-entitlement lifecycle events.
- Added RateLimiter: enumeration-resistant rate limiting per facade + opaque
  client key + route. Window-based counting with a separate consecutive cap.
  Both allowed and denied attempts are counted identically; callers cannot
  distinguish rate-limited from other denial reasons. Cleanup is time-based
  and self-expiring.
- Added ActivationStartHandler: validates product/facade from the authoritative
  registry, creates a pending registration via the repository, delivers the
  branded challenge via the mail adapter, and returns a masked envelope.
  Invalid/rate-limited input returns enumeration-resistant responses.
  No EDD customer, order, license, node, or lease is created during start.
  Idempotency keys prevent duplicate delivery; replayed requests return the
  same registration without resending email.
- Added ActivationStartPresenter: produces a safe, enumeration-resistant public
  result with masked email; never exposes raw email, verifier, poll credential,
  license key, or EDD internals.
