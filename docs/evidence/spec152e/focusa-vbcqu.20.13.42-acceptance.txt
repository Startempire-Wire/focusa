Bounded result
- One shared interactive flow (crates/focusa-cli/src/commands/
  activation_flow.rs) drives the shared ActivationSession for both the CLI
  (`focusa license activate-flow`) and the Rust installer; it contains no
  transition table and calls reduce_activation never (rendering only). The
  flow renders all ten frozen presenter states, prompts for email and the
  one-time verifier (never invents either), lists server-owned offers, and
  maps the §14.1 menu to the three journeys: existing key → existing_license,
  purchase → select_offer/checkout → bounded poll, Evaluation → Spec 172
  LimitedAccess intent (the authority decides eligibility; EVALUATION_NOT_
  ELIGIBLE fails closed). Wall-clock timeout and registration poll budget
  settle fail-closed via cancel (denied → recovery_only); recovery-only and
  non-retryable authority errors settle the local registration fail-closed;
  recovery_only accepts nothing (resume of recovery_only never re-grants).
- Resume: the flow persists a presenter-safe registration snapshot (private,
  mode 0600) plus the expiring poll credential in the protected store under
  a registration-scoped handle (added CredentialHandle::for_registration);
  `--resume <id>` re-supplies the credential and continues the bounded poll.
- Delivery: on terminal activation the flow parses the authority-owned
  LeaseDeliveryEnvelope, verifies key set + signed lease against the
  embedded production trust roots, and atomically writes the canonical
  authority state (PersistedAuthorityState::from_verified_envelopes +
  write_atomic); the encrypted one-time terminal key envelope is stored
  privately (never the plaintext key — the human key also arrives via EDD
  transactional email). Card PAN/expiry/CVC fields exist nowhere.
- Transport wiring (crates/focusa-license/src/activation_http.rs): the
  ActivationAuthority HTTP client promised by the shared client lands here —
  endpoints match the frozen call stack byte-for-byte, unknown error labels
  and malformed/oversized replies fail closed as AUTHORITY_UNAVAILABLE,
  policy validation is fail-closed (https-only).
- Installer: interactive terminals render the universal flow
  (installer/official_installer presenter identity); noninteractive
  installs keep the pinned device-code authorization
  (acquire_installer_entitlement). `--eval` maps to LimitedAccess intent;
  raw keys remain forbidden (E_AUTHORITY_RAW_KEY_FORBIDDEN), unsettled
  activation fails closed (E_AUTHORITY_ACTIVATION_UNSETTLED), and paid
  legacy migration remains required. Lifecycle models/orchestrator/receipts
  are verified unchanged: install/update still require a verified signed
  entitlement decision (EntitlementRequired/ProductGrantRequired/
  FeatureGrantRequired/EntitlementBlocked), receipts are product-ready only
  from a verified binding, and every denial state settles recovery_only.
