Bounded result
- Added the candidate EDD-bound lease issuer/signer seam. issueLease() issues a
  signed `focusa.authority_lease.v1` envelope ONLY after five canonical
  preconditions resolve in one transaction: (1) a verified authority account
  (wp_wpuiai_authority_accounts status active with mailbox_verified /
  account_promoted reason; EMAIL_VERIFICATION_REQUIRED / ACCOUNT_NOT_FOUND
  otherwise); (2) a usable canonical EDD license (wp_edd_licenses status active,
  unexpired, positive activation_limit, matching EDD customer;
  EDD_LICENSE_UNUSABLE / LICENSE_ACCOUNT_MISMATCH otherwise); (3) a settled EDD
  order and exact order item (complete order for the account customer, item
  matching the license download and the exact server-owned price;
  EDD_ORDER_PENDING / EDD_ORDER_UNVERIFIED otherwise); (4) the server-owned
  product grant resolved from the frozen registry by public product code only —
  features, limits, prices, tiers, commercial rights, and sequence are never
  caller-supplied (CALLER_CONTROLLED_GRANT_DENIED / PRODUCT_MAPPING_REQUIRED);
  and (5) a settled node bound to the account, the license, the product, and the
  presented device public key (NODE_NOT_FOUND / NODE_NOT_ACTIVE /
  NODE_NOT_BOUND / NODE_PUBLIC_KEY_REQUIRED otherwise). The EDD license is
  resolved from the node binding — the caller cannot select a license, order,
  customer, or price.
- Claims: every issued lease payload carries schema, lease_id, product, product
  code, posture, subject/account, customer, order, order item, EDD license,
  node, monotonic sequence, issued/not-before/expiry/offline-grace times,
  authority key id (kid), status, features, limits, and commercial grants. Paid
  (focusa_operator_lifetime_v1, price 697.00, expiry +90d, offline grace +30d),
  Evaluation (focusa_evaluation, price 0.00, expiry +30d, no offline grace,
  bounded subset features, node_limit 1), and bundle
  (focusa_uiai_operator_bundle_lifetime_v1, price 1254.60, exact-union
  features) postures are distinguished and server-derived.
- Signing: pure-PHP RFC 8032 Ed25519 via GMP (FocusaSpec152eEd25519Signer),
  domain-separated (FOCUSA-AUTHORITY-LEASE-V1\0 /
  FOCUSA-AUTHORITY-KEY-SET-V1\0), byte-compatible with libsodium, Python
  `cryptography`, and ed25519-dalek. The key-set seam reproduces the existing
  trusted Spec 152 Rust golden-vector key-set envelope byte-for-byte
  (root_public_key_b64 A6EHv/POEL4dcN0Y50vAmWfk1jCbpQ1fHdyGZBJVMbg=, identical
  payload_b64 and signature_b64), so the existing authority-lease verifier
  accepts the issued envelopes.
- Sequence: a per-account/product server-owned ledger
  (wp_wpuiai_authority_lease_sequences) issues strictly monotonic sequences;
  refund/revoke/expiry transitions advance the account entitlement sequence so a
  previously issued lease becomes stale and refresh is denied (STALE_SEQUENCE).
  A fresh lease after the transition jumps past the bumped sequence.
  previous_lease_digest chains when a prior lease exists. Idempotent replay
  returns the byte-identical lease; changed reuse of an idempotency key fails
  closed (IDEMPOTENCY_CONFLICT).
- Verification: verifyEnvelope() mirrors the existing verifier rules (envelope
  schema, key-set trust, key status/validity window, domain-separated signature,
  authority-key-id match, product/node match, minimum sequence, previous digest,
  status, not-before, expiry/offline-grace) and maps to Active / OfflineGrace /
  rejections (WRONG_PRODUCT, STALE_SEQUENCE, EXPIRED, REVOKED_LEASE,
  UNKNOWN_KEY, WRONG_NODE, INVALID_SIGNATURE, NOT_YET_VALID, REVOKED_KEY,
  KEY_OUTSIDE_VALIDITY).
- Golden vectors: docs/contracts/spec152e-lease-golden-vectors.v1.json pins the
  paid/Eval/bundle signed envelopes byte-exact with the PHP issuer output and
  the 8 negative envelopes (wrong product, stale sequence, expired, revoked,
  refunded → stale sequence at the post-refund sequence 45, unknown key, unbound
  node, invalid signature). No unverified-email promotion, local/self-issued
  entitlement, independent facade authority, client-controlled EDD price/grants,
  secret or unmasked real-email evidence, or publication (redaction scan
  asserts no '@', no 5x8-hex license key, no sk_/rk_/pk_ prefixes, no
  focusa_live_ synthetic keys anywhere in vectors, leases, or results).
