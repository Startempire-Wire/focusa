Bounded result
- Added one shared presenter vocabulary rendered identically by all four
  surfaces: the 10 frozen presenter states, the frozen next-action table,
  and one equivalent allowed-actions table (provide_email / verify_email /
  resend_code / select_offer / select_purchase / select_limited_access /
  select_existing_key / open_checkout / poll / deliver_license / activate /
  manage_nodes / refresh_lease / manage_account / resume / recovery / repair /
  export / uninstall / activate_or_manage_entitlement). The mapping is
  enforced per surface by the same frozen contract and cross-bound by the
  two exact-verification tests, so menubar, TUI, REST, and lifecycle receipts
  expose equivalent allowed actions, errors, and recovery for one canonical
  registration (checkout_required → [open_checkout]; payment_pending →
  [poll, open_checkout]; activated → [manage_nodes, refresh_lease,
  manage_account, resume]; denied → [activate_or_manage_entitlement,
  recovery]; recovery_only → [recovery, repair, export, uninstall,
  manage_nodes, manage_account]).
- Menubar: activationPresenter.ts projects daemon /v1/activation/status
  payloads into a typed MenubarActivationView (registration_id, shared
  state, terminal, next_action, allowed actions, validated masked email,
  authority-owned https link without credentials, retry posture, opaque
  resume handle); FirstRunWizard.svelte fetches and renders it (including
  denial/recovery posture) and EntitlementPosture.svelte shows the shared
  presenter state/next/allowed actions alongside the visual posture.
  Unknown states and unmasked identities fail closed; no raw email, key,
  poll credential, or card field exists by construction.
- TUI: activation_presenter.rs mirrors the frozen vocabulary and projects
  /v1/activation/status and /v1/license/status payloads into
  TuiActivationView / TuiLicensePosture (deterministic first-snapshot,
  fail-closed on unknown states/unmasked emails/bad links, terminal states
  carry no resume handle); app.rs stores them and deck_home.rs renders
  compact activation/entitlement lines that fail closed to "unavailable"
  instead of inventing a state.
- REST: /v1/license/status adds the presenter block with the shared
  presenter_state (active/offline_grace → activated; recovery_only →
  recovery_only; expired/revoked → denied; unactivated/legacy_migration_only
  → email_required), frozen next action, allowed actions, terminal flag,
  masked identity, and recovery policy; unknown labels fail closed to
  email_required / activate_or_manage_entitlement.
- Lifecycle receipts: presenter_posture() projects each receipt onto the
  shared vocabulary; a product-ready claim without a verified signature
  fails closed to recovery_only and never renders as activated; the posture
  struct carries no email/credential/card field.
- No unverified-email promotion, no local/self-issued entitlement, no
  client-controlled price/grant, no independent facade authority, no raw or
  unmasked email evidence anywhere; the shared reducer remains the only
  decision authority. Cargo/release builds remain deferred until the
  operator's 50% gate.
