Bounded result
- Added the paid-record migrator: the schema owns five tables —
  wpuiai_paid_record_journal (append-only, digest-chained), _imports (one row
  per accepted record), _evidence (Stripe payment_evidence / refund_evidence
  pinned 64-hex digests), _install_registry (noncanonical source rows), and
  _edd_mappings (exactly one EDD/account entitlement per accepted record).
- Evidence-first import: applyRecord() accepts a record only when its Stripe
  payment/refund evidence row and its install-registry source row exist and
  agree with the record handle; disposition unresolved has no evidence/registry
  and always fails closed with EDD_ORDER_UNVERIFIED — nothing is written.
- Verified identity before ownership delivery: applyRecord() demands a keyed
  64-hex verified-identity digest (never the raw email) that must match the
  record's pinned identity_lookup_digest; verify_first records deliver
  entitlement only after that gate (EMAIL_VERIFICATION_REQUIRED without it,
  EMAIL_VERIFICATION_FAILED on mismatch).
- One entitlement per accepted record: every accepted paid record resolves to
  exactly one imports row and one edd_mappings row, journaled once. Replays
  return the stored result (replayed=true) and never create a second
  entitlement or journal entry; the adverse-state journal is likewise
  idempotent.
- Never reactivate refund/revoke: refunded/revoked records are journaled
  `preserve_adverse_state` with the typed reason (REFUNDED/REVOKED), produce
  zero entitlement, and reactivate() always fails closed — there is no code
  path that can re-grant, re-import, or resurrect them.
- Preserved history where policy allows: product code, record status, masked
  key, and sequence are carried from the install registry into the
  imports/mapping rows — never from caller input; the server-owned product
  allowlist (focusa_operator / uiai_engine_operator / focusa_uiai_bundle /
  focusa_evaluation) rejects any caller-controlled product
  (PRODUCT_MAPPING_REQUIRED) and the decision signature has no price, grant,
  tier, limit, or feature inputs.
- Dry-run / apply / rollback-safe: dryRun() mirrors the exact apply gates and
  writes zero rows; applyRecord() is transactional and idempotent; rollback is
  preservation-only (preserveForRollback() writes a rollback_preserved event;
  no DELETE/TRUNCATE/DROP path exists) and can never delete EDD
  customer/order/refund truth, verified identities, licenses, nodes,
  sequences, credentials, Workpoints, Evidence, or migration journals.
- The journal is replay-safe: every entry carries previous_digest + entry_digest
  chained from genesis, and journalChainValid() recomputes the whole chain.
- No unverified-email promotion, no local/self-issued entitlement, no
  independent facade authority, no client-controlled EDD price/grants, and no
  secret or unmasked real-email evidence anywhere in the contract, fixture,
  or test output. Cargo/release builds remain deferred until the operator's
  50% gate; this atom touches no Rust surface, so no cargo build was run.
