Exact surfaces (this atom only)
- Registration device public key: FocusaSpec152eActivationRegistrationRepository::
  bindDevicePublicKey() records the registration's device X25519 public key and
  marks the one-time terminal delivery in one compare-and-set update; re-binding
  to a different device key fails closed (NODE_KEY_MISMATCH), replays are
  idempotent, and the plaintext credential is never persisted.
- Delivery envelope schema/service: docs/contracts/spec152e-terminal-delivery-
  envelope.v1.php — pure-PHP RFC 7748 X25519 (GMP) + HKDF-SHA256 + AES-256-GCM
  envelope sealing/open with canonical JSON claims that bind account, EDD
  customer, EDD license, product code, registration, issued/expiry, and a
  one-time flag; a delivery journal (wp_wpuiai_terminal_delivery_envelopes)
  enforces one envelope per delivery, idempotent replay, and retention; schema
  migration and preservation-only rollback are journaled.
- Poll response: FocusaSpec152eTerminalEnvelopeService::deliverPollResponse()
  returns the public-safe activation response with one_time_key_envelope
  (base64url sealed envelope) exactly once; a new poll after delivery fails
  closed with LICENSE_DELIVERY_FAILED; wrong poll credentials, expired
  credentials, malformed/mismatched device keys, pending or failed delivery
  posture, revoked licenses, and expired registrations all fail closed with the
  stable public codes.
- Credential adapter: FocusaSpec152eTerminalCredentialAdapter — protected
  credential-store seam; store confirmation exposes only the masked key and an
  opaque handle; one-time reveal is granted only under explicit customer
  consent and within the envelope lifetime, and a replayed reveal fails closed.
- Cross-language golden vectors: docs/contracts/spec152e-terminal-envelope-
  golden-vectors.v1.json — public synthetic fixture, byte-exact between the PHP
  contract and Python `cryptography` (RFC 7748 clamped exchange semantics,
  matching libsodium crypto_scalarmult).

Implementation commits: `e078f830` (envelope contract, registration device-key
surface, cross-language golden vectors, and both exact-verification tests).

Bounded result
- Added FocusaSpec152eTerminalEnvelopeCrypto: deterministic RFC 7748 X25519
  (pure PHP via GMP; passes RFC 7748 vectors 1 and 2 and the 1,000-round
  iterated vector), HKDF-SHA256 key derivation, and AES-256-GCM seal/open with
  the canonical envelope header bound as AAD. The PHP seal with the golden
  fixed inputs is byte-identical to the Python `cryptography` output, and the
  golden envelope decrypts to the exact canonical claims in both languages.
- Added FocusaSpec152eTerminalEnvelopeService::deliverPollResponse(): one-time
  terminal delivery through the activation poll response. The exact canonical
  EDD Software Licensing key (resolved only from wp_edd_licenses, active
  status, canonical hex pattern) is sealed to the registration's device public
  key with claims binding account/license/product/registration/expiry, the
  device key is bound on the registration, terminal_delivery_status becomes
  'delivered' with delivery_attempts and delivered_at, and exactly one journal
  row is written. An idempotent replay returns the identical stored envelope;
  a new poll after delivery fails closed and never mints a second envelope or
  key. openForDevice() validates every claim fail-closed.
- Added FocusaSpec152eTerminalCredentialAdapter: store returns masked
  confirmation only; reveal returns the one-time decrypted key only under
  explicit customer-controlled consent within the envelope lifetime, and a
  replayed reveal fails closed.
- Added the registration device-key surface bindDevicePublicKey() with a
  one-line nested-transaction guard on the repository transaction helper so the
  poll response composes atomically with the existing idempotency journal.
- No facade/access/generic log, response, journal, or evidence contains the
  plaintext EDD key or any unmasked real email; journals store only the
  license_key_digest, license_key_mask, and the sealed envelope payload.
