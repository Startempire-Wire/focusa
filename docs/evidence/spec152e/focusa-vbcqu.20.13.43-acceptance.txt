Exact surfaces (this atom only)
- CLI --json: `focusa license activate-flow --agent --email <EMAIL>` begins a
  pending attempt (never invents an email, verification code, consent,
  payment confirmation, or license) and `--agent --resume <REGISTRATION_ID>`
  continues bounded polling; both return the typed
  `focusa.agent_activation_envelope.v1` JSON; full key output stays masked
  unless the customer explicitly opts in AND confirms
  (`--reveal-key --confirm-reveal`).
- daemon/API operation: `GET /v1/activation/status` in focusa-api projects
  presenter-safe envelopes plus resumable registration handles from the
  persisted `focusa.activation_registration.v1` snapshots; asserts no raw
  email, raw key, poll credential, or card data.
- Pi/agent tool envelopes: apps/pi-extension/src/activation-envelope.ts —
  deterministic `focusa.agent_activation_envelope.v1` builder with typed
  human actions, masked email/key, reveal gate, and the resumable handle.
- secret masking/reveal policy: masked email and masked key by default;
  `key_visible` only after explicit customer opt-in AND confirmation;
  one-time key envelope never appears in agent transcripts.
- resumable registration handle: opaque `registration_id` in every envelope;
  poll credential re-supplied from the protected store (hash-only at rest),
  never in snapshots; terminal registrations refuse further steps.

Bounded result
- Added `AgentActivationEnvelope` (schema `focusa.agent_activation_envelope.v1`)
  in focusa-license: typed presenter states, `human_action_required` +
  `human_action` (provide_email / enter_verification_code / select_offer /
  open_checkout_url / complete_payment_then_poll / reveal_or_accept_license),
  masked email, safe authority-owned links, `key_present`/`key_visible`,
  poll budget fields, bounded retry posture, safe next action, and the
  opaque resumable `registration_id` handle. The struct has no field for raw
  email, the one-time key envelope, the signed lease envelope, poll
  credentials, verification hashes, server credentials, signing keys, card
  data, or EDD-internal records — those cannot be serialized by construction.
- Added `AgentKeyReveal { reveal_key, reveal_confirmation }`: authorized only
  when BOTH are set; otherwise `key_visible: false` and no `masked_key_prefix`.
  `mask_key_prefix` masks a caller-held key to `FOCUSA-XXXX-XXXX-XXXX-XXXX`.
  The one-time key envelope is never exposed to agent transcripts; reveal
  returns only a caller-supplied masked prefix.
- Added `run_agent_activation` (begin: email creates a pending attempt and
  the envelope stops at the typed human action with the resumable handle)
  and `resume_agent_activation` (bounded poll within the registration budget
  and optional wall-clock timeout; terminal settlements end; every other
  state returns the typed human-action envelope + handle; timeout/budget
  cancel fail-closed to recovery_only; refund/revoke carry the typed error
  code and recovery next action). Agent mode never prompts, never guesses a
  verification code, never chooses a journey or pays, and never reimplements
  the reducer.
- CLI `license activate-flow --agent` emits the envelope as JSON; without
  `--email`/`--resume` it fails closed with
  `EMAIL_REQUIRED: agent mode never prompts...`.
- Daemon `GET /v1/activation/status` returns `registrations` (agent
  envelopes projected from persisted snapshots), `resumable_handles`
  (non-terminal registration ids), the canonical entitlement posture, and a
  `privacy` block asserting no raw email/key/poll-credential/card data.
- Pi/agent tool envelope module builds the same frozen envelope from
  daemon/API payloads; unknown states fail closed as human-required.
- No invented consent, payment confirmation, identity, or entitlement
  anywhere; no local/self-issued Evaluation; no card data; no unverified
  promotion (the shared 48-transition frozen reducer still governs).
