Bounded result
- Added the canonical authority-node schema/repository seam. registerNode() works
  only for a verified authority account (wp_wpuiai_authority_accounts status
  active with mailbox_verified/account_promoted reason; EMAIL_VERIFICATION_REQUIRED
  or ACCOUNT_NOT_FOUND otherwise) and a usable canonical EDD license
  (wp_edd_licenses status active, positive activation_limit, matching EDD
  customer, unexpired; EDD_LICENSE_UNUSABLE / LICENSE_ACCOUNT_MISMATCH otherwise).
  The node binds account UUID, EDD license ID, server-owned product code (frozen
  spec 172 protected-offer allowlist; PRODUCT_MAPPING_REQUIRED otherwise), device
  public key (bounded base64url token; NODE_PUBLIC_KEY_REQUIRED), and assurance
  class, and records activation/last-seen/deactivation timestamps plus
  node-limit reservation and settlement references.
- Atomic limit reservation: a per-account/product counter ledger
  (wp_wpuiai_authority_node_limits) is incremented with one conditional UPDATE
  (reserved_count < node_limit) inside the registration transaction, so
  concurrent activations serialize on the write lock and can never exceed the EDD
  product node limit (NODE_LIMIT_EXHAUSTED). The limit is read from the canonical
  license row's activation_limit — set by the spec 152E issuance adapter from the
  server-owned offer — never from the caller. A denied attempt creates no node,
  no reservation, and no idempotency row; the counter stays exactly at the limit
  (released exactly).
- Reservation/settlement lifecycle: two-phase reserve() (validated, committed
  'reserved' row occupying one slot), settleReservation() (binds the active node
  row, state settled, counter kept), releaseReservation() (state released, counter
  decremented exactly once, explicit reason), and the atomic registerNode() path
  (reserve+settle in one transaction with one idempotency record; failure rolls
  back everything). Replays are idempotent for every operation; changed reuse of a
  key fails closed with IDEMPOTENCY_CONFLICT.
- Explicit management and device history: deactivateNode() requires the owning
  account (NODE_NOT_FOUND otherwise), marks the node deactivated (never deleted),
  releases its slot, and re-releases the settled reservation; a deactivated node
  cannot be deactivated again (NODE_NOT_ACTIVE) and an already-active device cannot
  register twice (DEVICE_PUBLIC_KEY_IN_USE). After explicit deactivation the same
  device may register a fresh node, with the full history preserved in listNodes().
  recordLastSeen() journals active-node heartbeats idempotently.
- No unverified-email promotion, local/self-issued entitlement, independent facade
  authority, client-controlled EDD price/grants/node limits, secret or unmasked
  real-email evidence, or publication. Node/reservation/ledger rows and all
  returned structures contain no email address, no EDD license key material, and
  no secret material (redaction scan asserts no '@', no FOCUSA key prefix, no
  cus_/sk_ prefixes).
