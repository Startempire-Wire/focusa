Bounded result
- Added the bundle order/item/license policy contract: the bundle SKU
  `focusa_uiai_operator_bundle_lifetime_v1` is ONE commerce SKU/key at the
  frozen server-owned price USD 1254.60 (125460 minor units) that grants the
  EXACT union of the two underlying Operator v1 License Types
  (`focusa_operator_lifetime_v1` + `uiai_operator_lifetime_v1`) with one
  operator seat, three SHARED operator node identities, lifetime duration,
  whole-order refunds only in v1 (component partial refunds unsupported),
  no third independent feature catalog, and future products excluded.
  `resolve_bundle_order_policy` fails closed with ProductMappingRequired for
  any other code (Focusa, UIAI, unknown, prefixed) — the client can never
  steer the mapping or the price.
- Added one-account bundle orchestration: `resolve_bundle_activation` reads
  only the public bundle code from the caller; EDD ids, prices, tiers,
  grants, limits, and commercial flags are never accepted (the decision
  signature has no such inputs). It requires one verified `UiaiAccountIdentity`
  (AccountIdentityRequired otherwise), the account to hold BOTH exact product
  grants (BundleGrantRequired for Focusa-only accounts), strict
  `same_account_binding` on both lease subjects (BundleAccountMismatch), and
  the SAME shared node identity on both grants (SharedNodeIdentityViolation —
  never six unrelated activations). When both grants are active and bound, the
  atomic `BundleActivationProjection` carries the two exact
  `BundleGrantProjection`s (features/limits derived only from the two signed
  authority leases — no third hand-copied list), the frozen price, and the
  shared node identities. When one grant has not settled, the typed
  `BundlePartialActivation` reuses the SAME `order_handle` and
  `registration_id` (`no_duplicate_payment`, `no_duplicate_license`,
  `one_edd_order`, `one_account`) and identifies the pending grant with its
  typed reason (`grant_inactive_or_unbound` retryable → resume_poll_same_order;
  `grant_product_mismatch` non-retryable → authority_review). There is no
  silent partial success.
- Added the Focusa/UIAI presenters-and-leases adapter posture:
  `BundleAdapterPosture::from_bundle_authority` builds the bundle posture
  carrying both exact grant lease ids/sequences/digests on the SAME shared
  node identities only when both grants are active and bound to the one
  verified EDD account; incomplete or split postures fail closed with
  AdapterEntitlementPostureIncomplete.
- Added 5 Rust unit tests (bundle_activation) proving the frozen policy,
  both-product atomic activation on one account, wrong-code/Focusa-only
  denials, the typed recoverable partial state (same order/registration, no
  duplicate payment/license, retryable vs authority-review recovery), and the
  strict same-account/shared-node binding.
- No unverified-email promotion, no local/self-issued entitlement, no
  client-controlled EDD price/grants, no independent facade authority, no
  raw or unmasked real-email evidence, no third feature list anywhere.
  Cargo/release builds remain deferred until the operator's 50% gate.
