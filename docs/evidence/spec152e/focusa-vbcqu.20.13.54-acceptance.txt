Bounded result
- The migration canary runs ONLY after the authority cutover state is
  published: before publish, startCanary / dryRunCanary / reconcile /
  proveRollback all fail closed with CUTOVER_STATE_REQUIRED and write zero
  rows. After publish, the canary binds to the published state digest and
  asserts new_issuance=edd_authority_only, facade_role=
  presenter_and_bounded_proxy_only, spec158=excluded with an intact digest.
- Dry run first: dryRunCanary() computes per-cohort predicted decisions
  (import / preserve_adverse_state / quarantine with typed reasons) with ZERO
  writes and covers the whole bounded cohort (COHORT_BOUND=8).
- Bounded canary apply: runCanaryEntry() applies ONE cohort entry at a time
  and compares before/after COUNTS, DIGESTS, and STATUS against each entry's
  pinned vectors — a before mismatch fails closed with CANARY_BEFORE_MISMATCH
  and a divergent computed transition fails closed with CANARY_AFTER_MISMATCH
  before any write. Each applied entry writes exactly one deterministic
  sequence-ledger row (import_sequence / refund_sequence / revoke_sequence).
- EDD/refund/sequence truth (Spec 152E §18): refunded and revoked cohort
  entries end recovery_only with a monotonic sequence increment (refresh
  denied); imports end active; reactivate() always fails closed with REFUNDED
  or REVOKED — no code path can re-grant or resurrect an adverse record.
- Failure injection + retry: an injected failure quarantines the entry with
  zero writes (INJECTED_FAILURE_QUARANTINED); unresolved records are
  quarantined (UNRESOLVED_QUARANTINED); a retry returns the stored quarantine
  (replayed=true) and can never un-quarantine or grant the record. Replays of
  applied entries return the stored outcome with zero new rows.
- Reconciler (Spec 152E §17, §22.1): reconcile() recomputes EDD and authority
  digests server-side, requires every EDD refunded/revoked record to map to
  authority recovery_only/revoked (an authority lease still active for a
  refunded/revoked EDD record — a missed callback leaving stale access — fails
  closed with RECONCILIATION_MISMATCH), requires quarantined records to hold
  no lease and the quarantined set to equal the cohort's quarantined entries,
  and is idempotent via recon_handle. Pinned digests recompute identically.
- Rollback-safety proof (Spec 152E §22.4): proveRollback() verifies rollback
  cannot undo (a) verified identity (every verify_first cohort entry keeps its
  pinned keyed identity digest), (b) EDD refund/revoke truth (adverse records
  remain recovery_only), (c) monotonic sequence (each applied entry's ledger
  sequence equals its pinned after sequence), and (d) audit truth (the
  digest-chained journal validates from genesis); a failed check fails closed
  with ROLLBACK_SAFETY_PROOF_FAILED. Schema rollback is preservation-only:
  preserveForRollback() journals rollback_preserved and no DELETE/TRUNCATE/DROP
  path exists anywhere in the contract.
- The canary converged with zero customer/license loss and zero authority
  rollback: 6 applied + 2 quarantined = 8 cohort entries, pending=0, 6 ledger
  rows == expected 6, every applied entry's ledger status/sequence equals its
  pinned after vector. Every unresolved record remained quarantined.
