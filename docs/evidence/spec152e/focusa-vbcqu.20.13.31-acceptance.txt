- Added the build-independent Spec 152E multi-domain facade acceptance suite:
  a deterministic, offline, replayable matrix over every registered facade
  domain (focusa_install_v1, focusa_marketing_v1, focusa_forge_v1,
  focusa_arena_v1, uiai_engine_v1, wpuiai_public_v1) and its exact origin.
  The matrix is driven by the generated facade registry and cross-checks the
  activation call stack, error registry, public OpenAPI, golden vectors,
  installer route manifest, deployed surface inventory, the browser security
  and website registration components, and the executable PHP facade
  contracts (probed through the CLI). No cargo build, no live network, no
  publication.
- Domain row: all six registered domains present with exact HTTPS origins,
  unique server-owned sender identities, registered-presenter status, bounded
  authority proxy capability, locale allowlist, and exact registry counts.
- Product row: all 14 allowed product bindings accepted; every allowlisted
  product is a registered protected EDD offer; cross-facade products
  (uiai-only offers on Focusa-only facades, base Focusa product on the engine
  facade) and invented/attacker products fail closed with FACADE_PRODUCT_DENIED.
- Link row: advertised verify/pay/success/manage/recovery transactional links
  equal the registered facade paths and are relative and version-stable; every
  facade path and success/cancel/recovery callback resolves against the exact
  origin as an HTTPS URL with no query, fragment, or version segment.
- Checkout-return row: select-offer -> checkout -> entitlement chain exists in
  the call stack; checkout is a registry proxy route, a public OpenAPI
  operation, and an install-facade page proxied to the registered facade path.
- Polling row: poll proxy route and OpenAPI operation; opaque poll credential
  stored keyed-hash only with registration/facade/action/expiry binding;
  retry-after bounded 3..30s; terminal states activated/denied/recovery_only;
  safe-retry, idempotent-retry, restart-verification, do-not-retry, and
  recovery-only retry rules; 202 poll errors; poll/verification hashes never
  exposed; masked email only.
- Recovery row: every facade exposes /activate/recovery and
  /activate/callback/recovery; recovery_only is terminal and reachable from
  denied/refunded/revoked/superseded/expired; EDD_LICENSE_UNUSABLE, REFUNDED,
  and REVOKED are 403 recovery-only; the outage link is the registered
  recovery page and recovery pages force recovery-only posture.
- Spoofing row: 15 origin/product/route/callback/locale spoof cases deny with
  the registry contract codes; all 16 caller authority fields deny with
  FACADE_REQUEST_FIELD_DENIED; all 9 required fields are enforced; browser
  component denies spoofed origins, unsafe callbacks, forbidden body fields,
  caller product overrides, issuance methods, GET-with-body, and short CSRF.
- Timeout row: protocol skew bound 300s (FACADE_TIMESTAMP_DENIED), presenter
  session TTL 1800s, CSRF TTL 600s (executed through the PHP security
  middleware: an expired session is FACADE_SESSION_DENIED and an expired CSRF
  is FACADE_CSRF_DENIED); continuation tokens expire now+300 and are
  registration/facade/action/nonce bound; verification expiry codes are
  non-retryable with restart semantics; browser responses are no-store and
  continuation/session state is memory-only.
- Upstream outage row: AUTHORITY_UNAVAILABLE is 503 retryable with
  retry_or_use_recovery; the install facade executes a 503 recovery-only
  envelope that never issues a license, lease, node, or credential; the
  registry/OpenAPI/call-stack postures forbid facade issuance and
  customer/commerce truth; the deployed surface inventory shows WPUIAI.com as
  the sole canonical authority kernel and install.focusa.dev as a bounded
  facade; all 11 install page routes resolve to the registered proxy routes.
- Website/presenter row: the shared registration presenter produces an
  identical eight-state semantic flow across all four branded website pages
  (Focusa, Focusa Forge, Focusa Arena, WPUIAI) with brand-only differences;
  checkout return, polling, and recovery pages disclose authority
  confirmation/outage posture; browser security binds all six domains; the
  installer surfaces are bound by the browser security component and are not
  website-themed registration pages.
- Hygiene: golden vector signature and continuation verify; OpenAPI proxy
  paths equal the registry routes; every proxy route has a call-stack
  operation; browser bindings match the registry; no secrets, no unmasked
