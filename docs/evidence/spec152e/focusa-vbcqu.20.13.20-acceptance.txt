Bounded result
- Eligible verified customer receives exactly ONE verified_no_license limited-access
  issuance: one posture row, one signed limited-access assertion row, one journal row,
  one registered device node, authority sequence 1, duration `no_automatic_expiry`
  (permanent Spec 172 limited posture; no countdown, no timed Evaluation), grant source
  `authority_signed_limited_access_assertion`, and the canonical explicit Focusa
  limited-mode allowlist. No EDD order and no EDD Software Licensing key is created:
  wp_edd_licenses stays at zero for eligible customers, every journal row records
  edd_order_id = NULL and edd_license_id = NULL, and the posture/assertion schemas
  remain EDD-free by introspection (assertEddFree).
- Idempotent replay of an identical request returns the byte-identical result with no
  duplicate journal/posture/assertion/node row; a different request body on the same
  idempotency key fails closed with IDEMPOTENCY_CONFLICT.
- Dedicated EDD product/license mapping is explicit and server-owned: the eligibility
  matrix has exactly 7 rows (verified_eligible -> limited_access_issued;
  terminal_history_only -> limited_access_issued with terminal rows preserved and never
  reactivated; unverified_email -> EMAIL_VERIFICATION_REQUIRED; active_paid_customer ->
  paid_posture_preserved; prior_evaluation_duplicate -> evaluation_not_eligible;
  caller_mapping_control -> CLIENT_COMMERCIAL_FIELDS_FORBIDDEN; unknown_product_code ->
  PRODUCT_MAPPING_REQUIRED).
- All bypass/downgrade/repeat cases fail closed: unverified or missing-proof input
  (EMAIL_VERIFICATION_REQUIRED) creates nothing; an active paid EDD license preserves
  paid posture (PAID_POSTURE_PRESERVED) with the paid license row untouched and never
  downgraded to limited mode; a prior Evaluation (including a facade-switched repeat
  with a new request key, node, and facade) denies the duplicate
  (EVALUATION_NOT_ELIGIBLE) with no new posture/assertion; refunded/revoked/expired/
  cancelled EDD history is preserved and never reactivated (the refunded license row
  stays terminal; no new EDD key); registration/account mismatch
  (ACCOUNT_EMAIL_MISMATCH), unknown authority account (ENTITLEMENT_REQUIRED), and
  registration/customer mismatch (EDD_CUSTOMER_RESOLUTION_FAILED) fail closed before
  any creation.
- Journal is bounded and redacted: every decision row (3 limited_access_issued,
  1 paid_posture_preserved, 1 evaluation_not_eligible) is scanned for raw email,
  key material, and customer secrets and contains none; rollback is preservation-only
  and never deletes journal rows.
