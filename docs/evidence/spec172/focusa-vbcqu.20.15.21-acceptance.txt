Bounded result
- Added the canonical Spec 172 Section 6.3 public-observe/action/persistence
  classification `UiaiActionPersistenceClass` (`PublicObserve` / `Action` /
  `Persistence`) with a coarse capability-class projection
  (`operation_class()`): only public observation is local base integration;
  action and persistence always resolve as remote/premium capability.
- Added the canonical Focusa UIAI operation map `SPEC172_UIAI_OPERATION_MAP`
  (21 server-owned rows, `UiaiOperationMapEntry`): the six
  verified-no-license public-observe operations (public_search,
  source_to_markdown, public_page_read, accessibility_snapshot, screenshot,
  basic_diagnostics), browser mutation (click/fill/type/select/press/submit),
  persistence (cookie/auth-state/session), authenticated/private targets,
  unattended automation, scheduled/batch QA, and premium hosted resources
  (premium proxy, hosted capacity, paid model calls). Every row binds a
  limited-mode family label and a paid UIAI Operator v1 family feature; rows
  cannot be extended, renamed, or reclassified by callers.
- Added `classify_uiai_operation` (exact operation-id lookup; unknown,
  prefixed, aliased, and empty ids fail closed) and the product-isolation
  adapter `resolve_uiai_operation_capability` — the shared Focusa/UIAI entry
  point browser, proxy, MCP, and taskgraph adapters call BEFORE any child
  token is minted or any UI side effect runs. It consumes only the canonical
  operation id and authority snapshots (`focusa_parent`, `uiai_grant`,
  `active_session_count`, `now`); product, price, License Type, family,
  feature, limit, node, and commercial rights are never caller-controlled.
- Enforced the observe-only limited mode and paid action boundary:
  - verified no-license: exactly one foreground, ephemeral, public-observe
    session (session_quota 1); a second concurrent session is denied
    (`LimitedModeRestricted`);
  - every action/persistence/hosted operation fails closed in limited mode
    (`UiaiGrantRequired`) before any side effect;
  - paid UIAI/Bundle proceeds only for granted paid Operator v1 family
    features (`PaidFamily` bound to the parent Focusa lease and UIAI grant
    sequence); persistence requires the `uiai_persistence` grant, browser
    action the `uiai_browser_action` grant, scheduled/batch QA the
    `uiai_batch_responsive` grant;
  - authenticated/private targets, unattended automation, premium proxies,
    hosted capacity, and paid model calls carry NO canonical paid feature, so
    they fail closed (`FamilyNotGranted`) even for paid grants (Spec 172
    Section 7.2: paid UIAI never includes paid proxies, hosted compute, paid
    model usage, or authenticated/private targets unless explicitly listed);
  - Focusa-only paid entitlement never grants UIAI
    (`FocusaOnlyCannotGrantUiai`); no posture at all fails closed
    (`MissingPosture`); unknown operation ids fail before any decision
    (`UiaiOperationError::UnknownOperation`).
- The existing child-token broker (authority-only issuance, same-EDD-account
  binding, cached-token revalidation rejecting stale parents and widened
  tokens) remains the post-decision gate; cross-product widening can never
  mint or reuse a child token. No anonymous product capability, no
  local/self-issued grant, and no caller-controlled commercial right was
  added; no data deletion or blocked basic export/repair/rollback/security
  update/uninstall exists in this surface.
