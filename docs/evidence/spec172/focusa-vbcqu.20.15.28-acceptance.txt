Bounded result
- Desktop has ZERO local entitlement authority: the bridge is pure with no
  module-level mutable state, holds no prices, grants, sale status, License
  Type records, or local commercial tables, and never accepts a
  caller-controlled product, price, License Type, family, feature, limit,
  node, or commercial right. The frozen vocabulary (7 postures, 3 License
  Type codes, 13 Spec 172 §21 stable errors, 9 retained-access entries,
  4 upgrade actions, recovery action, `grant_inferred_from_surface: false`)
  is byte-identical to the CLI/Pi/agent presenter fixture and the frozen
  registry `docs/contracts/spec172-license-types.v1.yaml`.
- Desktop has ZERO direct-storage mutation bypass (Spec 172 §11.4): the
  bridge contains no storage/reducer/sqlite/authority-store path by
  construction (`direct_storage: false`); every value-producing desktop
  action carries a daemon route and `forwards_to_core_guard = true`
  (derived only from `path.starts_with('/')`); mutation-capable actions
  number exactly 9 and all forward to the shared core execution guard.
  Unknown or unregistered actions fail closed before execution (Spec 172
  §12); the bridge never evaluates entitlement itself (presenter_must_not:
  evaluate_entitlement / reject_before_daemon_call).
- Desktop decisions are IDENTICAL to CLI/API: the desktop projection renders
  the canonical `focusa.spec172.presenter_projection.v1` envelope with the
  same frozen vocabulary and the same base-denial mapping as the CLI
  presenter (`spec172_base_denial`: unverified→EMAIL_VERIFICATION_REQUIRED,
  refunded/revoked→RECOVERY_ONLY, expired→LICENSE_TYPE_REQUIRED,
  missing/corrupt→ENTITLEMENT_POLICY_UNKNOWN, wrong product→
  PRODUCT_NOT_INCLUDED); the 24 desktop action rows map onto the same 17
  canonical operations as the menubar action map with identical
  family/method/route/mutation-class parity (family counts: account_recovery
  11, base_focusa 8, team_remote 2; mutation:true = 9).
- Same-node identity (Spec 172 §7.3): `SPEC172_DESKTOP_SAME_NODE` renders
  the frozen sentence (Desktop/CLI/TUI/Pi/menubar/Cockpit on the same node
  do not consume separate nodes) and the bridge holds no node counter; the
  Desktop never registers a node or multiplies activations.
- Limited read/export/recovery preserved and paid families blocked (Spec 172
  §17): the frozen 9-entry retained-access set is never disabled; the
  locked-state fixture names the canonical upgrade/recovery action
  (`activate_or_manage_entitlement`) and never disables read, export,
  recovery, repair, update, or uninstall; the paid families (team_remote,
  automation, release_proof, premium_updates, customer_data_export) are

- Release artifact workflow gates the desktop release artifacts on the exact
