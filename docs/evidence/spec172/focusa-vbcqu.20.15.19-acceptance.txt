Acceptance summary:
- Added ActiveProjectGuard with check_mutation that enforces exactly one
  mutable project in verified-no-license posture. Mutation in the explicitly
  selected active project is allowed; mutation in a second project denies
  with DeniedSecondProject carrying upgrade/switch action; mutation without
  any explicit selection denies with DeniedNoSelection requiring operator
  choice.
- Paid entitlement (BaseProductDecision::Entitled) bypasses the project
  guard entirely — the base product gate handles the rest.
- ActiveProjectSelection persists to ~/.config/focusa/active-project-selection.json
  with schema "focusa.active_project_selection.v1".
- switch_active_project and persist_active_project_from_path provide
  explicit switching — always permitted, preserves all project data, never
  deletes. clear_active_project_selection removes the persisted selection.
- Added evaluate_entitlement_execution_for_project wrapper in the
  entitlement execution guard that applies the project guard only for
  BaseFocusa ValueMutation operations with AllowVerifiedLimited reason
  (verified-no-license posture). All other postures and families pass
  through unchanged.
- Read projection and customer data export remain always available
  regardless of active project selection — verified by
  verified_limited_project_read_export_always_available and
  verified_limited_project_export_always_available tests.
- No activity heuristics are used; no data is deleted; the guard is a pure
  function of posture + explicit selection + project root.
