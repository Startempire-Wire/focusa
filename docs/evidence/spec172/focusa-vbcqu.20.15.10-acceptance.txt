Bounded result
- Verified promotion creates exactly one account posture: `recordPosture()`
  accepts only `mailbox_verified` / `account_promoted` input with a canonical
  `verified_at`; identical replays return the same posture row and never create
  a duplicate (one posture per account, product scope, and node). Unverified,
  pending, or missing-verification input fails closed with
  `EMAIL_VERIFICATION_REQUIRED` and creates no posture and no node row.
- The posture row binds the promoted authority account, the verified email
  identity, the verified registration, product scope (`focusa` | `uiai_engine`,
  server-owned), registered operator node (opaque node id + canonical digest),
  explicit family allowlist (canonical sorted JSON, validated against the
  server-owned Spec 172 limited-mode registry), monotonic authority sequence,
  issue/refresh times (canonical UTC), server-owned signer, and status.
- Caller-controlled product codes (`focusa_evaluation`), blocked paid families
  (`automation`, `release_proof`), and unknown families all fail closed with
  `PRODUCT_NOT_INCLUDED` / `CAPABILITY_FAMILY_NOT_INCLUDED` and create no rows.
- The signed-access-assertion repository records an authority-signed
  limited-access envelope from an active verified posture: wrong product scope
  (`ENTITLEMENT_PRODUCT_MISMATCH`), unbound node (`NODE_LIMIT_REACHED`), paid or
  unknown families outside the posture allowlist (`CAPABILITY_FAMILY_NOT_INCLUDED`),
  non-positive and stale non-existent lower sequences
  (`ENTITLEMENT_SEQUENCE_ROLLBACK_DENIED`), missing posture
  (`EMAIL_VERIFICATION_REQUIRED`), and revoked/superseded posture
  (`VERIFIED_LIMITED_ACCESS`) all fail closed with zero rows. Replays with the
  same (posture, sequence) or the same refresh idempotency key return the same
  assertion.
- Bounded-credential refresh rotates sequence and refresh window without
  imposing any access expiry on the permanent posture; revoke is
  preservation-only (status flip, never deletion). Rollback contract is
  preservation-only for both schemas.
- No EDD Software Licensing key and no zero-dollar fake license is created:
  the fixture asserts `wp_edd_licenses` stays at zero, and `assertEddFree()`
  introspects both schemas and proves no assertion or posture row contains any
  EDD license/order/customer/product, key, price, amount, total, currency,
  License Type, download, or grant column.
