Bounded result
- Added the canonical Spec 172 Section 11.3 UIAI Cockpit action registry
  `SPEC172_COCKPIT_ACTION_REGISTRY` (33 server-owned rows,
  `CockpitActionMapEntry`), each carrying Spec 172 Section 12 trusted
  operation metadata: action_id / product_owner (registered `focusa` |
  `uiai_engine`) / operation_class (registered `read` | `value_mutation`) /
  capability_family / side_effect_class (registered `none` | `local` |
  `remote` | `external`):
  - 10 Focusa-owned rows: 5 display/read (`cockpit.focusa.display_mission`,
    `display_workpoint`, `display_trajectory`, `display_evidence`,
    `read_projection`) and 5 value-mutation (`mutate_project`,
    `mutate_mission`, `mutate_workpoint`, `mutate_evidence`,
    `run_work_loop`), all bound to the `base_focusa` base product gate;
  - 21 UIAI-owned rows, one-to-one with the canonical
    `SPEC172_UIAI_OPERATION_MAP` vectors (`cockpit.uiai.public_search` ...
    `cockpit.uiai.paid_model_calls`), each binding its canonical UIAI
    operation id so the observe-only limited / paid Operator v1 boundary
    applies unchanged;
  - 2 combined workflows (`cockpit.combined.research_apply`,
    `cockpit.combined.observe_and_capture`), UIAI-owned composites
    (`combined_workflow: true`, family `combined_focusa_uiai`) that invoke
    both products.
- Added `classify_cockpit_action` (exact action-id lookup; unknown, prefixed,
  aliased, and empty ids fail closed) and the product-isolation adapter
  `resolve_cockpit_action` — the single entry point every Cockpit action
  resolves through BEFORE any UI side effect. It consumes only the canonical
  action id and authority snapshots (`focusa_snapshot`, `uiai_snapshot`,
  `active_uiai_sessions`, `now`); product, price, License Type, family,
  feature, limit, node, and commercial rights are never caller-controlled,
  and no pairing/auth/device input is accepted (pairing proves identity
  only, Section 11.3).
- Per-operation behavior by owning product (no window-wide blanket grant):
  - Focusa read/display: `FocusaDisplay { base }` reachable for Entitled AND
    Limited (verified no-license) postures; rendering Focusa state in the
    Cockpit never grants mutation — `permits_focusa_mutation()` is false for
    every display decision; a UIAI-only account with no Focusa posture gets
    `FocusaDisplayDenied`; a no-posture account gets the same;
  - Focusa value mutation: `FocusaMutation { base }` only when the base
    product gate is Entitled (one usable signed Focusa lease or valid
    Offline Grace); Limited and Denied postures get `FocusaMutationDenied`;
  - UIAI observation/action: delegated to the canonical UIAI boundary
    (`resolve_uiai_operation_capability`), so limited mode yields exactly one
    foreground ephemeral public-observe session
    (`VerifiedNoLicensePublicObservation { session_quota: 1 }`; a second
    concurrent session denies), Focusa-only accounts deny
    (`FocusaOnlyCannotGrantUiai`), paid UIAI/Bundle proceeds only for granted
    paid Operator v1 family features bound to the parent Focusa lease and
    UIAI grant sequence (`PaidFamily`), and hosted/private rights
    (`premium_proxy`, `hosted_capacity`, `paid_model_calls`,
    `authenticated_private_dashboard`, `unattended_automation`) carry no
    canonical paid feature so they fail closed even for paid grants
    (`FamilyNotGranted`);
  - Combined workflows: require BOTH the Focusa base grant (Entitled) AND
    the paid UIAI family (`UiaiOperationClass::RemotePremium` forced, so
    limited mode and no-grant both deny) — i.e. both grants or the Bundle
    (the exact union of the two underlying grants, Section 9/20.7). A
    verified no-license limited Focusa posture denies with
    `CombinedLimitedModeDenied`; missing Focusa or UIAI grants deny with
    `CombinedMissingFocusaGrant` / `CombinedMissingUiaiGrant`; cross-account
    UIAI grants fail closed through the shared same-account binding;
  - unknown action ids fail before any decision
    (`CockpitActionError::UnknownAction`).
- The registry is server-owned static metadata: no anonymous product
  capability, no local/self-issued grant, no caller-selected product, price,
  License Type, family, feature, limit, node, or commercial right, and no
  presenter-owned policy was added; no raw email, key, token, customer row,
  credential, or card data appears anywhere in the surface; no data deletion
  and no blocked basic export/repair/rollback/stable security
  update/uninstall exists in this surface.
