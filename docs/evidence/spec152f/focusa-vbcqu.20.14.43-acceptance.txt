Bounded result
- Replayed all 63 golden-vector cells against the canonical resolver: every
  fixture state/family pair (case_id `state::family`, exactly once) resolves
  to the frozen posture/reason pair, including the Spec 172-bound
  `verified_no_license` row (base_focusa = allow_verified_limited; all four
  optional premium families = deny) and the `internal_maintenance` inherit
  rows.
- Proved the resolver is deterministic and fails closed: repeated reductions
  are identical for all 7 states × 9 families; internal maintenance without
  an initiating posture is MissingInitiatingPolicy/Deny and with one
  inherits it; serde rejects `"evaluation"` and `"unknown"` state spellings
  while `"verified_no_license"` round-trips as a first-class posture.
- Proved API/core parity: for every guard-representable state
  (PendingUnverified, ActivePaid, OfflineGrace, RefundedOrRevoked,
  MissingOrCorrupt) × all 9 families, the focusa-core execution guard
  (`evaluate_entitlement_execution`) returns exactly the resolver's posture
  and reason for allow/read/base/feature cells and fails closed with the
  matching code for denied cells (ENTITLEMENT_BASE_REQUIRED for base_focusa,
  ENTITLEMENT_REQUIRED otherwise, ENTITLEMENT_ROUTE_UNCLASSIFIED for
  missing-initiator internal maintenance). The API route gate matches the
  same grid: base mutation POST /v1/workpoint/checkpoint passes only with a
  valid signed lease (Active or Offline Grace), premium routes
  (/v1/silent-sessions, /v1/connect/room/create, /v1/release/proof/status,
  /v1/update/scheduler) are denied for blocked states and for active-without-
  grant (ENTITLEMENT_FEATURE_REQUIRED) and pass only with the exact
  authority-owned feature grant; expired leases are denied at the lease
  validation boundary exactly like the resolver's Expired row.
- Proved premium grant isolation: a caller can never separately purchase or
  self-issue a premium family — without the snapshot grant the core guard and
  API gate deny, with it they resolve to Feature; stored premium feature
  claims never widen the base gate (only product + policy state decide;
  wrong products and non-usable postures stay Limited/Denied).
- Replayed the recovery matrix: stable update, repair, rollback, export
  (run/status/history/manifest), node deactivation, pairing status,
  diagnostics, and license status routes are never denied in missing,
  unactivated, refunded_or_revoked, or expired states, matching the
  resolver's AccountRecovery/CustomerDataExport Allow and ReadProjection
  Read rows (pending_unverified read_projection is Deny — unverified
  accounts get no read projection).
- Spec 172 overlay: the grid is bound to `verified_no_license` (an
  account/runtime posture, not a license, not Evaluation) and to Operator
  License Types only — focusa_operator_lifetime_v1 and
  uiai_operator_lifetime_v1 are the only LicenseTypeCodes, Operator v1 freezes
