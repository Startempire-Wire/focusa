Bounded result
- Added `LimitReservationService` (Spec 152F §6 chokepoint 4): atomically
  reserves limited premium operations before execution and settles them
  afterward. Every reservation re-resolves the canonical premium family
  decision (`resolve_premium_family` / `resolve_export_packaged`), reads
  capacity only from authority-owned `snapshot.limits`, and binds each grant to
  the lease identity (sequence + digest) and the issuing product/node/account
  scope (`ReservationScope`).
- Idempotency: replaying the same idempotency key returns the identical grant
  without double-reserving; the same key with a different payload, bucket, or
  scope is a typed conflict; replay against a superseded lease is stale.
- Exhaustion and concurrency: capacity is checked against outstanding
  reservations in the same scope at reserve time, so a race between arrivals
  can never double-allocate; settlement releases capacity for later requests.
- Stale state: expired leases, refunded/revoked postures, offline-grace closure,
  and higher authority sequences (changed sequence/digest) fail closed at
  reservation, revalidation, and settlement.
- Feature/limit registry: `DECLARED_SERVER_OWNED_LIMIT_BUCKETS` (frozen, 8
  buckets) plus `family_limit_buckets` map the four premium families (and
  export packaging) to their declared server-owned limit buckets; caller-
  invented features, caller-invented buckets, cross-family features, and wrong
  products are rejected before any capacity is touched.
- Product fixtures: deterministic authority-shaped fixtures for the four
  premium families + export packaging, plus six adversarial cases (wrong
  product, Evaluation omission, Offline Grace expansion, stale lease,
  cross-account, caller feature). Synthetic identifiers only; no real
  customers, keys, tokens, or PII.
- Export packaging fail-closed hardening: `resolve_export_packaged` now denies
  any snapshot whose entitlement state is not Active paid or valid Offline
  Grace (new `EntitlementStateNotUsable` denial) — a stored packaged-export
  claim or client metadata can never widen a pending, refunded/revoked, or
  corrupt state. Basic customer-data export remains always available.
- The four premium-family tests each gained an adversarial isolation case
  (wrong product, Evaluation omission, Offline Grace expansion, caller
  feature), and a dedicated 14-test adversarial matrix
  (spec152f_premium_adversarial.rs) drives all ten required steps through the
  reservation service and fixtures.
