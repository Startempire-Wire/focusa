Bounded result
- Added the canonical Spec 172 UIAI operation classification
  (`UiaiOperationClass`): local base integration (`PublicObservation`) versus
  remote/premium capability (`RemotePremium`). The classification is authority
  metadata; it is never caller-selected and never grants capability alone.
- Added `resolve_uiai_capability(...)`, the one parent-policy decision every
  UIAI/browser/proxy/MCP operation resolves before any child token is minted
  or presented:
  - verified no-license -> exactly ONE foreground, ephemeral, public-web
    observation session (`VerifiedNoLicensePublicObservation{session_quota:1}`);
  - paid UIAI Operator/Bundle -> the granted paid UIAI family
    (`PaidFamily{family, parent_lease_id, parent_sequence, uiai_grant_sequence}`)
    bound to the current parent Focusa lease and the UIAI grant sequence;
  - Focusa-only paid entitlement -> `FocusaOnlyCannotGrantUiai` (Spec 172
    section 3 item 7 / section 20 gate 5: Focusa-only never grants UIAI);
  - unknown postures, blocked/unknown limited families, ungranted paid
    features, caller-invented feature identifiers, different EDD accounts, and
    unbound grants fail closed with typed denials.
- Added `SPEC172_UIAI_PAID_FAMILY_FEATURES`, the frozen authority-owned set of
  seven UIAI Operator v1 family features (uiai_public_observation,
  uiai_browser_action, uiai_persistence, uiai_diagnostics, uiai_proof_packets,
  uiai_batch_responsive, uiai_supported_integrations) matching the EDD
  bundle-isolation contract. No Focusa feature satisfies a UIAI family.
- Added `authorized_cached_token(...)` on the broker: a cached child token is
  revalidated against the CURRENT authority snapshots before execution and is
  rejected when the parent lease id/sequence/digest is stale, the UIAI grant
  is revoked/stale, the token is expired, or the token's stored feature set is
  no longer an exact subset of the current grant (widened tokens fail closed).
  Cached tokens now also store node, features, and limits from the envelope.
- Independence from pairing/auth authority: the decision and revalidation
  consume only authority snapshots and operation metadata; pairing, device
  proof, authentication state, and caller-selected products/prices/grants
  never appear in the decision path. The UIAI issue #5 local task system and
  browser/proxy/MCP adapters use `resolve_uiai_capability` +
  `authorized_cached_token` as the pre-execution gate.
