Bounded result
- Every authority-relevant EDD transition deterministically changes the projected EDD
  license state and the account's monotonic authority sequence: order completion ->
  active/allowed (+1); refund and partly_refunded -> refunded/recovery_only (+1);
  chargeback (Stripe disputed/lost) -> refunded/recovery_only (+1); manual revoke ->
  revoked/recovery_only (+1); suspend (EDD SL disabled/inactive, EDD Recurring
  suspended/failing, Stripe past_due/unpaid) -> suspended/denied (+1); unsuspend
  (license active, Stripe won) -> active/allowed (+1); expiry -> expired/recovery_only
  (+1); subscription cancellation -> cancelled/recovery_only (+1); upgrade ->
  superseded/recovery_only (+1) with the new license completing independently; downgrade
  -> superseded/allowed (+1); reissue -> active/allowed (+1) from the reversible
  suspended state only; email_change and deactivate_node are audit-only hooks (+0,
  sequence unchanged). Applied result sequences are strictly monotonic 1..18 with no
  duplicates; the final account sequence is 18 after 18 entitlement transitions and 2
  audit hooks.
- Stale entitlement can never reactivate: a completion, unsuspend, or reissue event
  targeting a terminal state (refunded/revoked/expired/superseded/cancelled/denied)
  is journaled as 'denied' with LICENSE_TERMINAL_REACTIVATION_DENIED and leaves the
  state and sequence untouched (stale completion after refund, stale completion of a
  superseded license after upgrade, Stripe dispute-won after refund, reactivation of an
  expired license). Out-of-order delivery is bounded by the optional authority ordinal:
  a genuinely new event whose ordinal is not newer than the account's highest sequence
  is journaled as 'denied' with ENTITLEMENT_SEQUENCE_ROLLBACK_DENIED and can never roll
  the sequence back; the same event delivered in order applies normally. Duplicate
  redeliveries of an already-applied state (chargeback after refund, refund redelivery)
  are journaled as 'replayed' with sequence_increment 0; an identical idempotency-key
  replay returns the byte-identical decision with no duplicate journal row; the same
  idempotency key with a different digest throws IDEMPOTENCY_CONFLICT.
- Preservation-only truth: refund/revoke/expiry/cancel never delete the EDD customer,
  order, license, subscription, or audit history (row counts identical to the baseline
  after every transition; the refunded order row and refunded license row are retained).
  The lifecycle outbox journals exactly one row per hook delivery (27 fixture rows: 20
  applied incl. 2 audit hooks, 2 replayed, 5 denied), and rollback preservation records
  a schema event without deleting any journal.
- No raw email, raw payment/customer secret (stripe customer id), license key material,
  or unmasked real-email evidence appears in any journal row or decision payload
  (journal scans assert no '@', no 'cus_*' secret, no key material). No client-controlled
  price/amount/grants/features/limits/tier/download_id field is accepted
  (CLIENT_COMMERCIAL_FIELDS_FORBIDDEN); raw email input is rejected
  (INPUT_RAW_EMAIL_FORBIDDEN); unknown accounts fail closed (ENTITLEMENT_REQUIRED);
  customer/account mismatch fails closed (EDD_CUSTOMER_RESOLUTION_FAILED); terminal
  transitions with no prior entitlement (refund/suspend from nothing) are journaled
  denials (ENTITLEMENT_REQUIRED); unmapped statuses fail closed (EDD_STATUS_UNKNOWN);
  malformed request/idempotency/UUID/authority-sequence/state-reason inputs are
  rejected.
