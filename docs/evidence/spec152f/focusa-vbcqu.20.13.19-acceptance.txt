Bounded result
- Added the canonical EDD Software Licensing issuance adapter. issue() starts only
  from a settled_pending_issuance binding plus a pending ir_ issuance request; the
  canonical EDD order row (status complete, exact customer, exact verified email
  digest) and the exact canonical order item row are re-verified at issuance time;
  refunded/revoked/pending canonical truth fails closed (REFUNDED / REVOKED /
  EDD_ORDER_PENDING / EDD_ORDER_UNVERIFIED / ACCOUNT_EMAIL_MISMATCH) and never
  issues. The server-owned offer is the only product/price/duration/limit authority
  (PRODUCT_MAPPING_REQUIRED / EDD_CHECKOUT_REQUIRED on any drift or a frozen registry).
- One eligible order item produces exactly one canonical EDD SL key, forever, linked
  to the verified registration/account/customer and the canonical order/item rows.
  An idempotency-key replay returns the identical decision; a delivery retry with a
  new idempotency key returns the same key with existing=true and keys_created=0;
  a duplicate completion/issuance call never creates a second key, binding, or
  issuance journal row (canonical_licenses_created 4 for 4 issued items).
- Duplicate-key regression fixtures: synthetic focusa_live_* keys (inactive or active)
  block canonical issuance (issuance-level EDD_LICENSE_UNUSABLE; active synthetic also
  blocked at the binding boundary with EDD_LICENSE_UNUSABLE) and are preserved; an
  active canonical license for the same customer/download from another order blocks
  issuance (EDD_LICENSE_UNUSABLE, defense in depth); sibling items of the same order
  each issue their own key (two items -> two distinct keys) and the registration
  advances exactly once; an already-fulfilled registration with a pending sibling
  request issues its own key without disturbing the registration fulfillment
  reference. All adapter-issued keys are canonical EDD SL format
  ([0-9A-F]{8}-x3 groups); no focusa_live_* or synthetic prefix is ever produced.
- Registration fulfillment: the first order item advances the registration
  checkout_pending -> entitlement_issued with the canonical order/item/license
  references; registrations that never entered checkout fail closed with
  EDD_CHECKOUT_REQUIRED; denied/expired/terminal registrations fail closed
  (EMAIL_VERIFICATION_REQUIRED / REGISTRATION_EXPIRED); no-checkout denials leave the
  registration state untouched.
- No plaintext leakage: journals store only the 64-hex license-key digest plus a
  masked key; the full key is returned only inside the bounded fulfillment delivery
  envelope (focusa.spec152e.edd_license_delivery.v1) and is never written to any
  journal, decision outside delivery, or log. No raw email, raw payment transaction
  id, secret, or unmasked real-email evidence appears in decisions or journals
  (redaction checks assert no '@', no txn ids, no full-key pattern, no synthetic key
  material outside the explicit legacy fixtures). Rollback is preservation-only
  (issuance journals are never deleted; license rows are never deleted).
