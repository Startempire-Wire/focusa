Bounded result
- Added `require_release_proof()` to `crates/focusa-core/src/license.rs`:
  one canonical entitlement execution check against the `ReleaseProof`
  premium family with required feature `focusa.release.proof` and limit
  bucket `release_proof_runs`. Uses the same `evaluate_entitlement_execution`
  path as `require_base_product()` and follows the Spec 152F canonical
  decision order (P5: presenters never invent entitlement).
- Replaced the legacy `require_feature("official_release_bundle")` call in
  the CLI `ReleaseCmd::Prove` handler with `require_release_proof()`.
  The legacy path checked local license features outside the 152F
  entitlement policy; the new path goes through the canonical premium
  family resolution.
- Added `capability_family()` and `required_feature()` methods to
  `ReleaseOperation` in the release operation registry. Mutating release
  operations resolve to `ReleaseProof` premium; non-mutating operations
  resolve to `ReadProjection`. No caller-controlled product, price, grant,
  or feature input is accepted.
- Reclassified the `/v1/release/proof/status` route from
  `feature: "focusa.release.proof"` with `limit_bucket: Some("release_proof_runs")`
  to `feature: "focusa.core.evidence"` with `limit_bucket: None`. The
  endpoint is a GET that reads proof status; safe release status/read
  projection remains available without premium. Only advanced governed
  proof/orchestration operations require the release_proof premium grant.
- No base temporal/evidence capability is gated by filename. The
  classification is driven by operation semantics (mutation vs read), not
  by the presence of "release" in file paths.
