Bounded result
- Added the Pi/agent policy adapter (apps/pi-extension/src/entitlement-policy-adapter.ts):
  `resolveOperationPolicyForTool` resolves each tool's canonical operation
  policy from the canonical tool registry (FOCUSA_TOOL_CONTRACTS);
  `preflightAuthority` resolves operation policy BEFORE side effects and
  fails closed — unknown tools have no policy and block, value-producing
  mutations (base_focusa/automation/team_remote/release_proof/premium_updates)
  require a usable authority posture, and recovery/read families remain
  usable at the tool layer (the daemon still enforces its own security);
  `projectEntitlementDecision` returns stable machine JSON
  (`focusa.entitlement_decision.v1`): ok=false, status=blocked,
  failure_class=entitlement_blocked, canonical operation class/family/
  commercial treatment/required feature/limit bucket/recovery allowance, and
  a typed recovery object (status_path /v1/license/status plus allowed
  actions including export, repair, update_for_recovery, uninstall, safe_read).
  Commercial fields always come from the canonical contract — never from a
  caller-controlled payload.
- Authority boundary (Spec 152F §5): the adapter emits
  licensing_grants_capability_only=true and operator_authority_granted=false,
  cognitive_authority_granted=false, approval_inferred=false,
  discovery_visibility_granted=false by construction. Licensing grants
  capability only; operator permission/confirmation is preserved
  independently and never inferred from entitlement state; tool
  discovery/visibility is advisory routing metadata and never grants
  entitlement (`discoveryGrantsNothing`).
- Wired every Pi tool through the adapter in tools.ts inferToolResult (the
  single chokepoint all focusa_* tools flow through): ENTITLEMENT_* daemon
  denials now project the canonical `entitlement_decision` envelope,
  `entitlement_blocked` failure class, operator_required retry posture (never
  auto-approval), no side-effect claims, and recovery next-tools
  (focusa_agent_card, focusa_tool_doctor). FocusaToolResultV1 carries the
  optional entitlement_decision field; the tool-result output schema mirrors it.
- Extended apps/pi-extension/tests/pi-entitlement-gate.test.mjs to assert the
  adapter wiring and fail-closed/authority-boundary invariants, and added
  tests/spec152f_agent_presenter_test.py: presenter parity proving every one
  of the 136 Pi tools inherits its Agent Capability Descriptor V2 operation
  policy (policy_owner=entitlement_policy_resolver), descriptors never grant
  operator/cognitive authority or mutation confirmation, and discovery
  projections (pi-tools.json, openai-tools.json, mcp-tools.json, agent-card)
  are advisory-only with no entitlement grant fields.
