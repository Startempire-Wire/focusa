Bounded result
- Added FocusaSpec152eVerificationCompleteHandler: consumes exactly one valid
  challenge bound to registration/facade/action; validates facade/origin against
  the registry, enforces cross-facade binding (tokens from one facade cannot
  verify registrations on another), respects max verification attempts (5),
  delegates hash comparison/expiry/replay to the repository, and returns
  enumeration-resistant safe errors. Only a live matching challenge transitions
  the registration to email_verified. No EDD customer, order, license, node,
  or lease is created during verification.
- All negative cases return non-authoritative, non-enumerating errors:
  wrong verifier → EMAIL_VERIFICATION_FAILED, expired challenge →
  EMAIL_VERIFICATION_EXPIRED, cross-facade token → EMAIL_VERIFICATION_REQUIRED,
  nonexistent UUID → EMAIL_VERIFICATION_REQUIRED, already verified →
  EMAIL_VERIFICATION_REQUIRED, empty verifier → EMAIL_VERIFICATION_FAILED,
  max attempts → EMAIL_VERIFICATION_FAILED, wrong origin → FACADE_ORIGIN_DENIED,
  rate-limited → ACTIVATION_REQUEST_ACCEPTED.
- Cross-facade and nonexistent UUID errors are indistinguishable (enumeration
  resistance). Known and unknown facade origin failures are indistinguishable.
- Idempotency replay returns the same verified result without side effects.
- Challenge hash is cleared after successful verification; verified_at is set;
  verification_state transitions to mailbox_verified.
- Rollback preserves verified registration state (preservation-only).
