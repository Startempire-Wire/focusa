Bounded result
- Added the versioned signed capsule manifest contract (schema
  `focusa.capsule_manifest.v1`, manifest_version 1) binding capsule id and
  version, product and feature namespace, platform/arch compatibility,
  plaintext and ciphertext sha256 digests, the minimum compatible public-shell
  contract, required lease features and limit policy version, release channel
  and status, revocation state, provenance, and the node-bound key-envelope
  reference (`focusa.node_capsule_key_envelope.v1`).
- Added 26 synthetic manifest vectors (4 valid, 22 invalid) plus 4 forbidden
  schema-negative documents. Every vector is signed with a fixed public
  synthetic ed25519 signer key; deterministic canonicalization
  (sorted keys, compact separators, signature envelope excluded) is stored and
  replayed byte-for-byte by both the Python and Rust tests.
- Added public verifier types: `CapsuleManifest`, `CapsuleVerificationFacts`,
  `CapsuleVerificationDecision` (19 stable labels), `verify_capsule_manifest`,
  `canonical_capsule_manifest_bytes`, `capsule_manifest_sha256`. The verifier
  fails closed in fixed order on: unsigned/malformed signature envelope,
  unknown signer, invalid signature, unknown manifest/version/version shape,
  unknown product/platform/arch/channel/release status, unregistered required
  feature, unknown limit policy, missing/unknown key-envelope reference,
  revoked (manifest claim or authority facts), withdrawn, delivered-digest
  mismatch (modified payload), mixed installed version set, downgraded
  rollback, and incompatible runtime public-shell contract. Digest and
  signature authority live only inside the signed manifest; the schema closes
  the top level with `additionalProperties: false` so an unsigned sidecar
  checksum, embedded global key, or decryption key is rejected.
- Spec 158 implementation remains excluded; licensing can permit a capability
  but never selects or creates cognitive/Workstream authority.
