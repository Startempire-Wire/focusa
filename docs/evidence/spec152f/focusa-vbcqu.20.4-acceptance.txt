Bounded result
- Route classification now distinguishes public, recovery, safe-read,
  entitled-mutation, and execution routes. `route_requires_entitlement` no
  longer exempts every ledger-declared read: a declared-method ledger entry
  never exempts a route that resolves to an optional-premium family
  (`route_has_premium_policy`), so premium collaboration/automation reads
  (`/v1/connect/rooms`, `/v1/device/pair/list`) pass the entitlement gate while
  base reads (`/v1/workpoint/current`), recovery reads
  (`/v1/device/pair/status`), and declared public surfaces remain exempt. No
  route-name substring guessing was added; matching stays exact/template-based.
- The pre-handler gate now validates lease binding/current state before handler
  invocation: `route_entitlement_denial` returns early for every declared
  recovery/customer-control allowance (never lease-gated), and after the policy
  state grid passes, `entitlement_allows_mutation` re-checks that the lease is
  bound (non-empty lease id + `sha256:` digest) and current (Active with future
  expiry, or OfflineGrace within its window). Expired, revoked, unbound, and
  fabricated leases therefore deny value-producing handlers even where the
  state grid alone would allow them.
- With no signed lease at all, a premium-family operation reports
  `ENTITLEMENT_BASE_REQUIRED` (base gate is the first prerequisite) instead of
  the later-stage `ENTITLEMENT_REQUIRED`.
- Added a replay side-effect sentinel test proving that missing, invalid,
  expired, and revoked leases permit only the declared recovery surfaces and
  emit a denial sentinel for every protected mutation route (zero mutation
  sentinel events escape to handlers).
