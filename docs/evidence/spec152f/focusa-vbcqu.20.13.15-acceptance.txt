Bounded result
- Added the Spec 152E EDD gate hooks contract. Protected Focusa/UIAI
  offers exist only in the server-owned product registry and require an
  explicitly operator-approved mapping (mapping_status 'active',
  checkout_enabled, exact download and price). Caller metadata can never
  select a product, price, grant, limit, or commercial right
  (CLIENT_COMMERCIAL_FIELDS_FORBIDDEN).
- Added the verified-registration token validator: a token is minted only
  from a mailbox-verified, non-terminal registration, is bound to its
  exact registration, facade, and product, is short-lived (1800s TTL),
  single-use, stored only as a keyed digest, and bounded to 16 active
  tokens per registration. Replays are idempotent and never re-issue a
  raw token.
- gateAddToCart: raw add-to-cart (no verified token), unknown downloads,
  credit packs, wrong facades, wrong origins, unsupported facade
  products, and client product-claim mismatches are denied with
  public-safe stable codes; unrelated/quarantined products return
  non_entitlement_allowed with entitlement_allowed=false (purchasable but
  proven non-entitlement); a protected cart opens only with a valid
  single-use token bound to the verified registration.
- gateCheckout: requires an operator-approved active mapping with the
  exact server-owned price, a verified registration binding, and either a
  fresh single-use token or the journaled cart-gate binding; blocked
  mappings return EDD_CHECKOUT_REQUIRED, price mismatches
  PRODUCT_MAPPING_REQUIRED.
- handleOrderComplete (replaces the broad edd_complete_purchase hook):
  requires complete order status (pending/processing -> EDD_ORDER_PENDING;
  refunded -> REFUNDED; revoked -> REVOKED; failed -> EDD_ORDER_UNVERIFIED),
  verified registration/account binding with the order email matching the
  verified registration email lookup digest, allowlisted product mapping
  with the exact order-item price relationship, idempotent issuance state
  (journaled, replayable, IDEMPOTENCY_CONFLICT on key reuse with a
  different request), and no existing equivalent active license
  (EDD_LICENSE_UNUSABLE). Issuance itself stays deferred to the verified
  issuance service: the hook records a bounded decision only and creates
  zero EDD license rows.
- Credit packs and unrelated/quarantined order items are proven
  non-entitlement (no_entitlement / excluded_items); an order with no
  protected items completes with no entitlement and requires no
  registration. Rollback is preservation-only for token and gate-decision
  journals. Every decision payload is redacted: no raw email, raw token,
  license key, or secret, and no grant/feature/limit/price metadata.
