Bounded result
- Added `EntitlementDecisionCounters` (crates/focusa-license/src/observability.rs):
  fixed-capacity (9 family + 13 reason + 5 posture slots) atomic counters keyed only by
  canonical enum labels. `snapshot()` is label-only and can never carry lease ids,
  digests, customer identifiers, paths, keys, or tokens; caller-supplied strings cannot
  grow the counter set. Recording touches only enum discriminants.
- Added the `entitlement_policy` bench target (harness=false) covering exactly the
  required decision paths: hot cached decision (state-grid reduction), cold validation
  (full `ResolvedEntitlementPolicy` invariant checks), premium+limit decision (registered
  feature resolution plus signed limit reservation — the API middleware/scheduler
  revalidation resolver path), denial (base-product and premium missing-feature), and the
  policy registry load path (one validated schema+digest load plus warm cached lookups).
  All scenarios are deterministic, in-memory, and secret-free: no per-request file
  parsing and no network dependency.
- Added `SilentSessionDispatchMetrics` (focusa-core): bounded, label-only scheduler
  revalidation metrics derived from dispatch decisions, counting selections and the
  fixed deferral-reason set (including `EntitlementDenied`).
- API middleware observability tests (focusa-api) prove the route/operation registries are
  compiled in via include_str!, loaded exactly once through a OnceLock (pointer-identical
  across calls), resolve deterministically with no I/O, and that denial envelopes are
  bounded/static and secret-free.
- No enforcement was weakened: the state grid reducer, base-product gate, signed-lease
  binding, refund/revoke, node/sequence, recovery allowances, and EDD identity/commerce
  authority are untouched by this atom.

Performance budget and benchmark receipt (real run, release profile, remote OVH build)
- `cargo bench -p focusa-license entitlement_policy` — exit 0.
  Receipt (300,000 iterations each, deterministic in-memory fixtures):
  - hot_cached_decision:            0.4 ns/op
  - cold_validation:               19.3 ns/op
  - premium_plus_limit_decision:  977.7 ns/op
  - denial_decision:              139.0 ns/op
  - policy_registry_cold_load:    829,179 ns (one validated schema+digest load)
  - policy_registry_warm_lookup:   88.3 ns/op
  Budget: every per-request resolver/middleware decision is sub-microsecond on a hot
  cache, the coldest full validation is tens of ns, the registry loads once at process
  start (cached thereafter), and no path performs per-request file parsing or network I/O.
