Title: 152F.04.04 Split stable security maintenance from premium updates
Implementation commit: 48b2196d18100c9424a73f189dd8a820978bbee4

Exact surfaces
- crates/focusa-core/src/update.rs

Bounded result
- Added `UpdatePolicy::premium_update_required()`: returns `None` when the
  policy uses the stable channel with a manual mode (notify, prompt, manual) —
  these are always-available stable security updates and repair paths. Returns
  `Some("focusa.install.channel.preview")` for the Preview channel,
  `Some("focusa.install.channel.nightly")` for the Nightly channel, and
  `Some("focusa.update.unattended")` for Automatic or Scheduled modes. Dev
  mode is a dev-override and does not require premium features.
- Added `UpdatePolicy::is_stable_security_maintenance()`: returns true when the
  policy is safe stable security maintenance — stable channel + manual mode —
  that remains available even when commercial entitlement is blocked, expired,
  refunded, or revoked.
- The split ensures that manual stable-channel security updates, trust-metadata
  refresh, repair, and rollback remain available in blocked states (via
  RecoveryAllowance::StableSecurityUpdate mapping to AccountRecovery family),
  while premium channels (preview/nightly) and unattended apply remain
  authority-controlled via the PremiumUpdates capability family and their
  registered feature identifiers.
- Signature/trust verification, confirmation, and the existing recovery-route
  path in the API middleware are preserved unchanged.
