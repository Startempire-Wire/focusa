Bounded result
- Transactional append: every committed EDD/account change carries exactly one signed
  outbox row (order completion, order failure, refund, subscription cancellation,
  license expiry, customer promotion all journaled as pending events with zero attempt
  budget); an injected crash (rollback) removes the canonical change AND its outbox
  row together — no orphan rows, no committed change without its event. The hook
  snapshots the canonical authority sequence at append time (authority_sequence ==
  result_sequence) and never bumps it: the outbox records truth, lifecycle projection
  owns advancement (sequence stayed at 1 after an append at sequence 1).
- Dispatch is exactly once under injected crashes: a crash mid-delivery (consumer
  effect applied then process crash) rolls back the consumer effect and the delivery
  ledger together, leaving the row in bounded failed state (attempts=1,
  last_error=DISPATCH_DELIVERY_FAILED); the next retry redelivers exactly once
  (1 ledger + 1 consumer application for the event), so an injected crash/retry loses
  no event and duplicates no entitlement. Idempotent replay of a dispatched event
  returns the byte-identical existing delivery with no new ledger and no new consumer
  application.
- Durable failure state never blocks canonical EDD commit: a consumer-down saga
  retries with 60s/120s backoff (attempts 1 and 2 in failed state, bounded
  DELIVERY_CONSUMER_DOWN, then dead_letter at attempt 3) while the canonical refunded
  order stays committed and untouched; repairState() exposes exactly the bounded
  dead-letter record (event_type, attempts, bounded error, retention; never payload
  internals), retryDeadLetter() re-queues it, and the next cycle dispatches it exactly
  once. repair state returns clean afterwards.
- Bounded signed events: tampered payloads and tampered signatures are quarantined to
  dead-letter with OUTBOX_ENVELOPE_TAMPERED and are never delivered; an unknown
  signing key dead-letters with UNKNOWN_SIGNING_KEY; 3 tampered fixtures produce zero
  deliveries and zero consumer applications. All 9 committed events survive every
  crash/retry/tamper fixture in exactly one bounded dispatch state (6 dispatched, 3
  dead-lettered, nothing stuck pending, 6 deliveries, 6 consumer applications).
- Redaction and preservation: all outbox rows, signed payloads, delivery ledger rows,
  and repair-state JSON contain no raw email, no payment/customer secret, no license
  key material, no unmasked email evidence, and no signing secret; persisted failure
  codes are enumerable and bounded; rollback is preservation-only (schema event
  recorded; outbox rows and delivery journals never deleted); EDD customer/order/
  license/subscription history row counts are unchanged.
